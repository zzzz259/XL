当前维护版本为 Android 0.4（versionCode 15），主页面为底部三栏的移动端界面：记录、查询、我的。「记录」连续展示固定标题「招募档案」与总抽数/五星/卡池摘要（账号名只在顶部账号按钮出现，页内不再重复）、抽卡生涯与近 45 天评价（普通、限定、典藏三类展示抽数、出卡数或 UP/歪 数、五星平均或平均 UP；垫抽改为进度条叠字并入生涯卡，不再有独立的当前垫抽区块；启程不计入生涯附注，未分类记录另计）与十连多金、抽满井、连 UP、连歪等生涯标签，分类卡池（默认展开五星间隔，全部卡池的角色收获由「全部角色/收起角色」开关统一显示或收起），星级与卡池分布、原始招募明细折叠在页面底部，右下浮动「更新」与「分享（长图）」；「记录」统一为简洁布局（无「简洁/详细」切换及本地界面偏好），卡片、行距与边距更紧凑，五星间隔条约 24px，每条五星时间与本池第几抽、账号更新时间、卡池尾部次要说明、覆盖说明及标题旁次要文字一律隐藏，统计与原始数据不变；「查询」在页内提供官服网页登录、TapTap App 授权、常显的 B 服授权（未配置时禁用并标注「待接入」）与可正反面翻转的手动凭据（下方同一按钮切换，教程单独弹窗，返回键先关教程再翻回）及查询进度，不再使用登录对话框，也不再提供「保留官网会话」（每次登录固定开启新会话）；「我的」集中账号切换、改名、删除与导入导出、长图、游戏配置、查询回执和隐私说明。三栏记录访问顺序与每栏滚动位置，返回键先回上一栏并恢复其位置。0.3.6 及以前的更新见 [0.3.4 之后的更新公告](releases/gacha-v0.3.6.md)。电脑端最后版本为 0.3.4，现已停止维护与更新；下文电脑端说明仅供旧版参考。旧记录可导出 JSON 后导入 Android。

## 安装、打开和升级

Windows x64：下载发布者提供的便携 ZIP，完整解压到自己可写的目录，双击 `StarfallGacha.exe`。不要只复制 EXE，旁边 `_internal` 也是程序的一部分。启动器会打开默认浏览器；关网页不会退出程序，关闭启动窗口才会停止本机服务。重复启动同一目录会重新打开已有实例。端口变化、更换浏览器都不改变本地存档。

Android 9+：安装发布者提供的 APK，系统提示时允许从该来源安装。保留原应用并覆盖安装同 applicationId、同签名的新版本；签名不符不能直接升级。不要为了升级先卸载，否则本机记录会随应用删除。系统 WebView 需要保持更新。开发/CI 生成的新密钥包不能当成已有正式版本的升级包。

升级应用前先「备份全部」。Windows 保留旧程序旁的 `user-data/`，将它迁移到新程序旁；Android 同签名覆盖安装保留内部数据。换机器用 JSON 备份迁移，程序没有账号云同步。

## 登录与查询

Android 打开应用后，没有本机存档会直接进入「查询」，在「记录」空状态可点击「查询我的记录」，或在「我的」点击「登录并更新记录」；在「查询」页选择官服网页登录、TapTap App 授权、B 服授权（入口始终显示，未配置时禁用并标注「待接入」），或点击「手动凭据」将登录卡翻到背面，下方同一按钮变为「返回登录方式」并可翻回。渠道选择、导入与查询进度都在该页内展示，不再弹出登录对话框；每次发起登录都固定开启新的官网会话、不保留旧登录状态。官服在展示 `https://i.haoplay.com.cn` 的独立官方窗口完成短信或 TapTap 授权。验证由玩家本人操作。Windows 需要已有 Edge/Chrome 等兼容 Chromium 浏览器；「浏览器与环境检查」可诊断路径和连接，也可填写已有浏览器的可执行文件路径。Android 使用独立官方 WebView。

查询将官方当前可见的历史合并到对应 UID 与渠道的本地账号；不会写入当前选中的其他账号。官方返回范围有限，本工具累计保存已查询内容，不保证覆盖全部生涯。重复查询会去重，十连中重复的角色掉落会保留。

手动凭据入口供自动登录不兼容时备用：在登录卡背面粘贴本人官方会话的 JWT 或 HP 对象，并勾选「确认这是本人账号」。「获取教程」弹窗说明如何在电脑 Chrome/Edge 登录官网后，通过 F12 → Application（应用）→ Local Storage（本地存储）→ 官网地址，复制 `jwt` 的完整 Value 或 `HP_2070021` / `HP_2070023` 的完整 JSON 值。返回键先关闭教程，再翻回登录方式；查询失败保留输入和勾选，成功后才清空。凭据具有账号访问权限，不要发给他人、截图分享或提交问题附件。Android 第二账号切换已由用户复测确认。

Android 0.4 不再提供「保留官网会话」选项：在「查询」页每次发起登录都固定开启新的官网会话，不保留旧登录状态、不保存密码，也不写入抽卡存档；会话保留能力仍保留在原生实现中，仅界面不提供。Windows 0.3.4 及旧版界面的「记住官网登录」是旧版行为：勾选后 Windows 专用浏览器 profile / Android 官网 WebView 只保存自己的登录状态供下次少登录，删除保留的会话不删除抽卡存档。

## 账号、导入、导出和长图

在「本地存档」（Windows）或 Android 顶部的账号名与「我的」的当前存档卡片切换、改名或删除账号；删除只影响本机，不影响游戏。JSON 支持单账号导出和「备份全部」，推荐用于备份、跨平台迁移与合并。CSV 适合表格查看；新 CSV 保留卡池及存档身份，旧九列 CSV 缺少身份/卡池 ID 时会保守处理，不能唯一判断 UP 时显示未知。无身份文件默认建立独立存档，只有明确选择目标才合并。

导入失败不会部分写入一批内容。单文件最多 30 MB、最多 500 个账号，每账号最多 10 万条历史/100 万抽。历史内容冲突时拒绝合并，请保留原备份检查来源。不要用编辑后的 CSV 覆盖唯一原件。

「长图」导出当前分类统计与五星间隔；超高自动分张，最多 100 张。Windows 可下载 PNG 或整组 ZIP。Android 0.4 在「记录」点击右下浮动「分享」或从「我的 → 长图与分享」进入，可先选择导出分类。无网络也可浏览已存档内容、导入导出和生成长图。

Android 0.3.4 起提供长图相册保存和系统分享，0.4 界面中在长图预览勾选所需图片后点击「保存所选」或「分享所选」，也可逐张保存、分享，或「导出全部图片 ZIP」。保存后在系统相册的「星落抽卡手记」中查看，对应目录为 `Pictures/星落抽卡手记`；Android 10+ 无需读取整个相册的权限，Android 9 首次保存时按需请求存储写入权限，拒绝后仍可分享图片。

「分享」打开系统分享面板，由本人选择已安装的 QQ、微信等应用并确认发送；接收应用可能限制图片数量、大小或压缩画质，可减少勾选后分批分享。工具只准备临时图片，不额外存入相册或下载目录；取消分享也不会自动保存图片。临时缓存会在后续使用时清理过期文件。工具不会把打开分享面板误报为发送成功。

JSON、CSV、ZIP 仍作为文件导出，Android 10+ 保存到「下载/Starfall」，Android 9 使用系统文件选择器。相册长图用于查看和分享，迁移、恢复抽卡存档请保留 JSON 备份。

Android 在「查询」页每次发起登录都会新建官网登录会话，不保留或复用旧官网登录状态，等待本人完成授权；选择本地存档只改变查看对象。正式 APK 使用同一包名和签名覆盖升级，保留应用数据；名称带 QA 的独立测试应用不共享正式版数据，可通过 JSON 导出/导入迁移记录。不要卸载正式版后再升级。

### Android：使用已登录的 TapTap App

B 服玩家在「查询」页使用「B 服授权」：该入口始终显示，只有构建时写入 B 服私有配置的包才启用点击；普通 QA 包未提供配置，入口禁用并标注「待接入」（实现仍在，并非功能缺失）。配置启用后，在官方哔哩哔哩 App 确认即可自动识别账号并查询；与官服分开归档。每次 B 服查询都保留官方授权，无需手填 UID。0.4 界面不再提供 B 服诊断复制入口（脱敏诊断能力仍保留在原生实现中）。

0.3.6 起可选择「TapTap App 授权」（0.4「查询」页中的名称）。在官网阅读协议并选择 TapTap，等待手记窗口上方「打开 TapTap App」可用后点击。在官方 App 确认本次登录，通过系统最近任务返回手记，继续原网页的官网授权，随后自动查询。无需手动扫描二维码或填写 TapTap UID；官方授权确认仍需本人完成。

未安装、尚未登录或授权过期时，按页面提示重试，也可选择「继续网页登录」。授权有时限，请在同一次流程内完成；过期后重新开始。0.4 界面不再提供 TapTap 诊断复制入口（脱敏诊断能力仍保留在原生实现中）。国内 TapTap 的 MuMu 组合已验证，真机兼容性仍在验收。

### Android：QQ 授权后打开手机浏览器

0.3.3 保留 QQ App 授权，并提供浏览器分享入口：

1. 在工具中开始官网登录，在 TapTap 中选择 QQ，正常完成 QQ App 授权。请确认 QQ 安装在同一设备和用户空间。
2. 如果授权后打开了手机浏览器，停留在 `https://accounts.taptap.cn/social/callback/qq` 页面；不要关闭工具里原来的登录窗口。
3. 使用浏览器菜单中的「分享」或「分享网页」，分享**当前页面链接**，选择「抽卡手记·继续QQ授权」。部分浏览器需要展开「更多」才能看到工具。
4. 确认「继续登录」。工具会在本次登录原有的 TapTap 页面继续处理，之后自动识别官网登录状态并查询。

入口仅接受当前待完成登录对应的回调，检查 `state` 一致性，一次使用后不能重复提交。登录等待上限为 10 分钟；如果已取消登录、重新开始登录、原窗口关闭或应用进程被系统回收，请重新发起授权，分享最新页面。不要将授权链接分享给他人、群聊或问题附件。工具不保存该链接，也不会为旧回调另建登录会话。

浏览器已经跳转离开回调页、未能匹配当前会话，或授权码已在浏览器侧失效时，此流程可能不能完成；可重新授权或返回选择短信等其他登录方式。分享接收、会话校验和恢复窗口已通过本机合成测试；2026-10-23 用户确认 QQ → 浏览器 → 分享回工具的流程在真机可用。该确认不代表所有手机系统和浏览器均已覆盖，遇到差异仍可选择其他登录方式。

## 配置更新与统计

「游戏配置」（Android 在「我的 → 游戏配置」）默认使用内置正式地址 `https://8.134.186.234/gacha-config/current.json`，不需要首次手动填写。仍可改为维护者提供的其他 HTTPS 地址，已保存的自定义地址会保留；普通玩家不要填测试服务器数据。配置只更新角色名称、星级、卡池与保底规则，成功后打开已有记录会用原始 ID 重新计算，抽数和时间不变。失败继续用内置/最后验证成功配置。启动后台检查，正常成功后 6 小时内不会重复检查，也可手动刷新。

配置 JSON 更新不替换程序。界面/查询逻辑变更仍需更新 EXE 或 APK。内置基线为 134359843258232660；运行时以页面显示的已验证版本为准。

普通、限定、典藏分别统计，启程单独计数；跨卡池按配置的保底组继承。平均抽数为本分类可见总抽数÷五星数量，包括首个五星和当前垫抽。首个可见五星及断档后的间隔为「≥」，不能据此断言官方实时保底。序号 80→1 是连续循环，不自动视为断档；真正跳号保守中断推断。十连逐抽顺序尚未独立核验。

生涯卡中，限定/典藏的「平均 UP」与普通的「五星平均」是同一口径：本分类可见总抽数÷五星数量，歪出的五星同样计入，只是不单独区分 UP 与歪的出卡间隔；旁边的 UP/歪 计数分别列出两类出卡数。启程不计入生涯附注，未分类记录另计一行。

Android 0.4 结果页的角色头像一律用名称首字加星级色块占位，卡池 UP 角色 ID 从应用内置且已校验的 catalog 补充；不联网获取图片、不使用也不伪造真实头像，也不显示累计消耗金额。生涯与近 45 天评价、超欧/超非等事件标签按下面的口径计算，仅作回顾参考。

生涯与近 45 天评价只统计普通、限定、典藏中配置了硬保底的可见记录：生涯覆盖全部可见历史，近 45 天含两端且剔除未来时间戳的记录。暂无记录、样本较少、暂未见金、星级待确认时不评级；可评级但样本偏少（不足 100 抽或五星少于 3 个）会标注「暂估」。标签只来自有明确规则的事件：十连多金（含未知稀有度的按「十连至少双金」计）、按硬保底抽满（如「抽满 70 井」）、2 次及以上的连 UP 或连歪；没有规则依据的标签（如满潜）不会出现。

超欧/超非等事件标签来自本地 BaseWord_cn 静态规则的概率模型：五星基础概率 2%，UP 占五星的 50%；60 抽未出五星后概率由 2% 升至 7%，之后每抽 +5%；最多 70 抽必得五星；非 UP 后下一五星必为 UP。按该规则对状态做转移，得到首次出 UP 的 1–140 抽分布：超欧取累计分布约前 5%（≤6 抽），超非取约后 5%（≥122 抽）且该次不是大保底。前序不完整（间隔为「≥」）、非限定/典藏卡池或硬保底不是 70 规则的，不贴超非。评价阈值（评级用的均值分档）与事件分位（超欧/超非的 5% 分位）是两套不同口径，只描述已发生的可见记录，不是官方概率，也不是对未来抽卡结果的预测。

## 隐私、存储和求助

Windows 数据在 EXE 旁 `user-data/history.sqlite3`，配置缓存 `user-data/catalog-cache`；Android 记录在应用内部 WebView IndexedDB、配置在内部 files，清除应用数据或卸载会删除它们。只分享导出的脱敏副本；备份含账号名称、UID 和渠道，发布前自行检查。不要分享 Windows 的 `login-profiles/`。

游戏查询由本机直连官方服务；配置下载仅 GET 公共 JSON，不附带 JWT、UID 或抽卡记录。Windows 网页只访问本机回环服务，Android 主页面为内置资源。没有开发者云端记录上传接口。

打不开页面时先检查启动窗口、目录权限/端口和浏览器环境；登录失败先在官网确认会话，再检查浏览器或手机 WebView；配置错误先检查地址、HTTPS 证书和服务端 manifest，不要关闭证书验证。向维护者提供系统、应用版本、操作步骤、固定错误码及合成复现文件即可，不要提供 JWT、手机号、真实备份或登录 profile。
