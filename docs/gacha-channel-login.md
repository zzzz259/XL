# Android 渠道登录与诊断

0.3.6 在已验收 0.3.4 基线上增加 B 服与 TapTap App 授权，查询、分析、存档和导出沿用现有实现。

## B 服

使用本应用自己的包名和签名拉起官方哔哩哔哩授权页。玩家确认后，原生层通过游戏客户端 SDK 账号交换取得账号标识和 SDK 令牌，继续游戏认证、动态网关与历史查询。每次查询保留官方确认，不要求玩家手填 UID、root 或读取游戏目录。构建时的客户端 SDK 接入配置从 Git 外提供，不进入源码库；登录值不写入存档、日志、导出或诊断。

账号存档键包含渠道，B 服与官服的相同数字 UID 不会混为一个账号。卡池回执只记录返回码和数量，空历史与失败分开显示。实际游戏服务的历史保留范围仍以服务端返回为准。

## TapTap App

复用充值门户原有网页登录授权，保留其 PKCE/state 与回调。官方 TapTap 登录页生成本次扫码请求后，玩家点击原生按钮，交给固定的国内官方包 `com.taptap` 确认；手记保留原网页等待结果。玩家从最近任务返回并完成网页授权后，原门户继续认证，手记仅在官网白名单来源接收本次登录状态。

页面监听仅在 `https://accounts.taptap.cn/login` 生效，读取指定设备码端点的响应。原生层再次校验设备授权 URL 的 HTTPS 来源、路径与参数，挑战绑定当前会话和窗口代次，一次使用后清除；导航、取消、会话变化和超时使旧挑战失效。没有向第三方页面注入手记原生桥，也不读取 TapTap 私有数据。未安装、取消或过期时保留提示及网页登录备用。

手机布局会隐藏官方扫码切换入口，App 授权模式仅在该官方授权窗口调整布局 UA，保留原请求的 state、PKCE 与回调；选择网页登录时恢复原 UA。同时跟踪页面内路由变化，准备超过 15 秒仍无响应时提供重试和网页登录提示。授权确认后仍由玩家手动返回手记。

## 验证与限制

MuMu API35、国内 TapTap 2.96.10 与 WebView110 的包内流程完成四池查询，分别返回 80、80、3、80 条，共 243 条记录、1746 抽；重复导入没有重复累计。B 服在已有角色的新账号上通过四池空历史查询。隔离 Android 检查覆盖 App 交接、链接策略、会话与窗口变化、未安装 App、过期、旧状态清理、QQ 回流及图片导出分享。

用户在 vivo V2162A / Android 14 / WebView 116 / TapTap 2.95.0 的实体手机上确认修复后的授权查询通过。更多 App/WebView 版本、国际版 TapTap、系统回收进程以及 B 服非空历史仍需持续验收；不能由单台真机或模拟器结论推断全部兼容。诊断只含版本、设备环境、固定步骤、布局准备状态、结果和耗时，不含 UID、设备码、完整授权 URL、令牌或抽卡明细。具体命令见[构建与测试](gacha-development.md)。
