# Android 0.4 信息与界面重构

## 目标与基线

以 `d2a78d13` 的 Android 0.3.6 为基础，把桌面网页的信息结构改为移动应用。包名仍为 `cn.starfall.gacha.local`；0.4.0 的 versionCode 为 15，增加欧非与十连高光的 0.4.1 为 16。正式包继续使用原签名覆盖升级，不卸载、不清除数据。

用户补充的参考界面以账号、生涯分类统计、当前垫抽、卡池和横向出货条为主要层级。卡池默认展开；角色全集等次要内容仍可按需展开。0.4.1 根据用户后续要求增加透明规则的娱乐欧非评价，不引入全服排名或未被服务端提供的实时概率。

## 原界面问题与新结构

原页面在统计前常驻账号管理、配置、登录选项和桌面说明。三列生涯统计与表格在手机上缺少独立布局，多种操作权重相同。

| 页面 | 主要内容 | 默认与返回行为 |
|---|---|---|
| 记录 | 当前账号、累计抽数/五星/卡池、生涯分类、垫抽、展开卡池、原始明细、长图 | 已选中存档时进入；切页保留滚动位置 |
| 查询 | 官服网页、TapTap App、B 服、登录选项、进度、取消、备用凭据 | 无存档时进入；切页不取消正在运行的任务 |
| 我的 | 账号与备份入口、游戏配置、诊断、帮助、隐私、版本 | 管理信息不再占据记录首页 |
| 账号面板 | 原账号选择器、改名、删除、添加、导入、备份、JSON/CSV | 使用真实业务控件；删除仍由原逻辑二次确认 |
| 长图面板 | 当前导出范围、生成进度、张数、图片预览、相册、系统分享、ZIP | 首张自动预览；原生返回先关闭面板 |

有账号但未选择时，记录页提供选择存档入口。查询与导入完成后展示刚保存的账号。后台配置重映射更新数据时保留当前页面和分类，不强制跳回记录。

## 功能分层

高频：查看记录、分类切换、重新查询、生成及分享长图。中频：切换或添加账号、搜索原始记录、导入。低频：改名、备份、CSV/JSON 导出、配置地址和使用帮助。删除是需要确认的数据操作；渠道诊断放到“我的”，不占据记录首页。

分类总览在三个卡片里展示招募数、五星/歪和平均抽数；单分类展示完整指标及保底说明。普通池不使用“歪”口径。首个可见五星和断档继续显示 `≥`；UP 未知保留未知。当前垫抽显示已累计未出五星的抽数，不表述为“距下个五星还差多少”。

## 表现层与业务连接

`xl_gacha_android/web/mobile-index.html` 提供独立 Android DOM，`mobile-ui.css` 提供完整样式，`mobile-ui.js` 负责页面导航和移动卡池渲染。`build.py` 复制共享业务脚本后，以该模板替换 APK 的 `index.html`。B 服入口仍受构建配置开关控制；未配置时隐藏，不发送无效授权请求。

| 节点/状态 | 所属逻辑 | 重构后的作用 |
|---|---|---|
| `state.report/category/page/busy` | 共享 `app.js` | 仍是统计、分类、原始记录分页和查询状态的来源 |
| `account-select`、改名/删除/导入/备份 | 共享 `local.js` + Android IndexedDB 适配 | 移入账号面板，保留事件和接口 |
| `portal-start`、`tap-start`、`bili-start`、`portal-cancel` | 共享 `login.js` + 原生桥 | 放在查询页，继续官方授权、轮询和取消 |
| `report-shown` | 共享 `app.js` | 默认显示记录；`preserveView` 标志用于后台刷新 |
| `library-changed`、`report-cleared` | 共享页面状态事件 | 同步空状态、账号摘要、导航与管理按钮 |
| `GachaPresentation.renderPools` | 可选表现层扩展 | Android 使用展开卡池，Windows 沿用原渲染器 |
| `export-image`、`image-dialog` | 原 `image-export.js` | 复用生成、相册、分享和 ZIP；仅重做面板样式 |
| `MainActivity.onBackPressed` | 原生容器 | 先处理最上层弹窗，再调用移动页面历史，最后交给系统 |

`showReport` 的事件 detail 仍是原报告，新增的 `preserveView` 不改变数据契约。Windows 的 HTML/CSS 不变；共享脚本只增加可选渲染入口和状态通知，后台刷新也可保留当前分类。

## 视觉规范

颜色集中在 `mobile-ui.css` 顶部变量：底色 `#101821`、表面 `#1b2632`、较高表面 `#24313e`、文字 `#f2efe8`、次级文字 `#a7b3bf`、强调 `#dfc28b`。出货条的青绿、金色、暖红及未知蓝灰只表达既有间隔与记录状态。

主要标题 24–27px，模块标题 18–22px，正文 14–16px；总览指标按可用空间排布。间距以 4/8/12/16/24/32 为主，主要按钮至少 48px，次要触控至少 44px。导航和工具图标为内置 SVG，不加载远程字体、图标或图片。星形角色标记为通用装饰，不冒充角色头像。

系统栏 Insets 继续由原生 FrameLayout 处理，CSS 不重复追加系统栏高度。支持 `prefers-reduced-motion`；大字体允许换行。按用户后续要求，所有宽度下的卡池均为单列，包括平板和横屏。分类条可横向滚动并在记录浏览时吸顶，不引起整页横向滚动。

## 性能与完整性

卡池和五星记录默认展开，超过 20 项分批追加；顺序和统计不改变，不把批次之外的数据当作不存在。全部角色列表展开后按 40 项追加。原始明细沿用共享搜索、卡池/星级筛选与每页 20 项的分页。

不修改认证、网关、协议、统计算法、账号身份规则、去重、IndexedDB 名称/版本、配置更新协议或 PNG 生成算法。登录网页仍是独立 WebView，原生桥仍只注入本地应用页面。正式包不包含 QA 原生宿主、真实个人数据或研究脚本。

## 0.4.1：近 30 天评价与十连高光

`mobile-insights.js` 是独立的派生统计模块，不修改 `MobileEngine`、原报告的 analysis schema 或个人存档。已保存的历史打开后即可计算，无需重新查询。

近期取设备当前时间之前的滚动 30 天，包含下界，不计未来记录；总生涯取全部已存档可见历史。两者均随当前分类切换。普通、限定、典藏按已确认硬保底参与；启程、未分类和硬保底未知的记录排除。存在未知星级时不评级；少于30抽显示样本较少，少于100抽或3个五星标记暂估。

娱乐分档按 `Σ(每条记录抽数 / 对应硬保底) / 已知五星数`：不超过0.3/0.5/0.7/0.9依次为欧皇/偏欧/平稳/偏非，超过为待转运。平均出金另按实际参与抽数÷五星数展示，包含当前垫抽。30抽以上尚无五星显示暂未见金，不以无穷平均数评分。UP/歪不参与该分档，也不生成概率或百分位。

十连高光只统计同一原始记录总量恰好10且已知五星至少2个的批次，支持双金至十金、同角色多份、批次去重和未知星级下界。相邻两条五抽或同秒单抽不会拼成十连。全局按当前分类汇总次数，卡池与对应五星行标记同批多金；识别不依赖已被注明未独立验证的真实十连内部出货顺序。

新增验证覆盖30天边界、旧历史、未来记录、评级各阈值、分类/硬保底、无五星/少样本/未知星级，以及双金/三金、重复批次、非十抽和未知下界。宽屏视觉检查和原生检查均要求卡池处于同一列；大字体同时检查评价卡片内部边界。
