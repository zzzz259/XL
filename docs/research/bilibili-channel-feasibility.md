## 本轮实验记录

E1–E4 初始离线阶段使用项目 `.venv/Scripts/python.exe -B`，没有调用真实认证/游戏业务接口。所有临时输出位于 `E:/AI-Agent/OpenAI-Codex/bilibili-channel-research/`。后续 E5 经用户授权在内存读取正常 SDK 会话并调用一次真实认证，Frida 检查使用现有研究虚拟环境；未安装新依赖，未输出 SDK 密钥或账号数据。

### E1：包体身份与配置

- 问题：B 服是否另有游戏认证入口？
- 依据：现有工具只访问昊游认证服务器。
- 方法：解析两份 AXML、流式 SHA256 全文件索引、读取配置 TextAsset。
- 结果：B 服包名、版本和 SDK 不同，但 android_cfg 的认证/客户端服务 URL 相同。文件规模和版本不一致，不能将所有差异归为渠道。
- 判定：认证入口可优先复用；H2 的“必须不同入口”不成立于此静态样本。

### E2：渠道身份如何进入游戏认证

- 问题：SDK 登录成功后是否需要先自行构造 PnSDK JWT？
- 方法：只追踪 BSGameSdkCenter、回调桥、LoginWindow、LoginMgr、LoginService。
- 结果：SDK `uid/access_token` → LoginCallback → LoginData `openId/token` → 相同游戏 `/login` → 动态地址 → EnterGameReq。未发现要求查询工具先自行签 JWT 的步骤。
- 判定：不应复用当前限定 HP 应用的 JWT 解析器处理任意 B 服 SDK 回调；也不能将成功登录 B 站网页视为取得此 SDK 游戏令牌。
- 下一步：正常授权会话下确认实际 `LuaUtil.GetChannel()` 与设备字段来源，再做一次受限验收。

### E3：协议及数据复用

- 方法：对照 B 服包内 Proto 与现有官服更新资源 Proto，断言八种目标消息完整字段定义和四个命令 ID 一致；构造虚构 GachaRecord，交给现有 Python decode_records、merge_records；检查同外部 UID 不同 channel 的账号键。
- 结果：五组检查全部通过。使用现有测试执行 core 2 项、archive 12 项、network 3 项，共 **17 项通过**。
- 边界：合成解析和账号键测试不等于 B 服真实查询；未运行 Android B 服原生认证、未重新构建发行包、未进行长图真机回归。本轮未改这些业务模块。
- 结果文件：研究目录 `offline-contract-results.json`。

### E7：自动 UID 探索，首次填写入口保留

用户接受首次填写作为当前备用方案，并要求继续探索自动取得。当前 B 站 9.16.1 的正常 SSO 入口静态确认只返回 access_key。19:06 两条官方账号接口分别返回 `-101/-663`，没有 UID；19:13 游戏认证省略 openId 仍返回 0，但仅返回网关地址与时区；19:17 无 openId 的角色态握手虽然响应为 0，却返回 actorExist=false，不能定位此前已确认存在的角色，也没有 UID 可提取。

本轮自动分支没有手填 UID、Cookie、SDK 密钥或原版私有数据输入，没有发送创建角色和历史查询。尚未建立可靠自动 UID 路径，保留已实测成功的手填 + 官方确认方案；身份尚未解析时不得把 actorExist=false 当成“该用户新号无角色”。详细证据见 [授权入口研究](bilibili-channel-authorization.md)。

失败单独标注为输入/凭据类型、HTTP/代理、认证服务 retCode、网关地址策略、EnterGameRsp、actorExist 或历史查询拒绝。不能统一写成“不支持 B 服”。

## 首条路径验证后，最小产品改造范围

这部分是候选设计，尚未实现，也不是已获厂商支持的承诺。

| 层 | 必要改造 | 可保留能力 |
|---|---|---|
| 授权入口 | Android 首选官方 App 显式授权 + SDK 签名交换自动取得 UID/令牌；保留玩家确认与手填备用。Windows 授权需独立选择并验证 | 当前官服门户登录 |
| 会话模型 | 区分 provider、game_channel、credential_kind、device_id、外部账号及游戏角色；B 服令牌不假设为 JWT，也不要求含 GUID claim | 官服现有 JWT 校验 |
| 认证/网关 | 共享编解码和服务器验收；将固定 `haoplay_cn` 改为受验证适配器提供；基于实际网关调整严格白名单 | 消息帧、响应限长、超时、actorExist 检查 |
| 身份及存档 | 明确渠道/区服/角色命名空间，旧官服键兼容迁移；禁止不同渠道自动合并 | 历史合并、增量积累、去重、JSON/CSV |
| 数据配置 | 验证 B 服选择器、卡池和角色配置版本，必要时分别分发公共 catalog | 原始记录、重映射、统计、长图 |
| 错误/隐私 | 分阶段错误、取消登录、凭据失效不复用、敏感值不入普通存档和日志 | 既有本机数据原则 |

当前 Windows 认证函数使用 `ProxyHandler({})`、浏览器使用 `--no-proxy-server`，Android `systemProxy()` 返回 NO_PROXY。这是恢复时发现的既有产品行为，本轮没有改变；用户在 E5 前明确更正为游戏直连，因此不再要求游戏实验经本机代理，外网下载和 GitHub 仍遵守代理约定。

目前已有可行授权输入及一次空历史实测，可围绕已验证路径设计产品接入；尚未将临时探针当作正式客户端发布。无需重复哈希、官服历史恢复和全量反编译。
