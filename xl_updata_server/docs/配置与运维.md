# Update Server 配置与运维

配置模式定义于 `server_app/config.py`，样例默认值见 `config.toml.example`。部署用的 `config.toml` 含密钥和路径，不提交。

## 配置项

| TOML | 用途 | 示例默认值/约束 |
|---|---|---|
| `[server].timezone` | 调度时区 | `Asia/Shanghai` |
| `[server].normal_interval_seconds` | 常规轮询间隔 | `3600`，必须为正数 |
| `[server].burst_interval_seconds` | 密集模式间隔 | `60` |
| `[server].burst_duration_seconds` | 密集模式最长时间 | `1200` |
| `[server].burst_anchor` | 密集周期锚点 | `last_friday` 表示配置时区最近一个周五 10:00，每 21 天一轮；也接受带时区偏移的 ISO datetime |
| `[paths].data_dir` | 持久数据目录 | 相对配置文件目录解析，默认 `data` |
| `[paths].java_bin` | Java 可执行文件 | 默认 `java`，可配置绝对路径 |
| `[paths].unluac_jar`、`unluac_opmap` | Lua 反编译器和 opcode map | 样例指向相邻 `xl_updata_tool/tools/lua/` |
| `[paths].node_bin` | Node 可执行文件 | 默认 `node`；renderer 要求 Node 20+ |
| `[paths].character_card_font` | 可选 CJK 字体 | 空值时使用 renderer 系统字体搜索 |
| `[cdn].base`、`categories` | CDN 地址和下载类别 | 当前只支持 `Arts`、`Data` |
| `[cards].enabled` | 是否渲染图鉴卡片 | 默认 `true`；关闭时只处理角色数据 |
| `[security].assetbundle_key` | 资源处理密钥 | 必须为 16 个 UTF-8 字节；生产配置不得公开 |

改完配置先使用 `run_server.py --once` 做单次验证。修改周期锚点时检查目标时区和首次检查时间，避免意外密集轮询。

## 安装依赖

目标服务器安装 Python 3.11/3.12、Java 21。创建服务端自己的 venv 并安装 Python 依赖：

```bash
cd /home/admin/xl_updata_server
bash scripts/install_server.sh
bash scripts/install_renderer.sh
```

renderer 还需要 Node 20+、Cairo/Pango/JPEG/GIF 系统库与 node-canvas。`scripts/install_renderer.sh` 会调用 `dnf` 并运行 npm 安装，需 root/sudo 且会更改系统软件包；执行前确认发行版仓库的 Node 版本满足 `renderer/package.json`。渲染 Node 进程的堆上限为 512 MB，以控制低配服务器的内存使用。

```bash
bash scripts/check_server.sh
.venv/bin/python -m pytest -q
```

`check_server.sh` 检查配置、unluac、Python 模块、Node renderer、Java 和 Python 源码编译；它不能证明远端 CDN 或真实长图渲染结果正确。

## systemd 运行

`deploy/xl-updata-server.service` 默认路径为 `/home/admin/xl_updata_server`。换部署目录时检查 unit 的 `WorkingDirectory`、`ExecStart` 和配置文件路径。

```bash
mkdir -p ~/.config/systemd/user
cp deploy/xl-updata-server.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now xl-updata-server.service
systemctl --user status xl-updata-server.service
journalctl --user -u xl-updata-server.service -f
```

用户服务要在 SSH 注销后继续运行，需由管理员为该用户启用 linger。Unit 设置 `Restart=on-failure`、`Nice=10`、`CPUQuota=100%`、`MemoryHigh=700M`、`MemoryMax=1G`。

`scripts/run_full_production.sh` 提供独立目录的一次性低并发验证，不移动正式服务 current 指针。按脚本输出和生成的 manifest 检查；不要用 shell 后台化或 `nohup` 代替 systemd 管理。

```bash
./scripts/run_full_production.sh
systemctl --user status xl-updata-full-production
journalctl --user -u xl-updata-full-production --no-pager
```

该脚本的报告写在 `data/full-production-<时间>/`，检查 `manifest.json` 中的数据、皮肤、长图成功/警告/失败统计。它不会改动 `data/current_version.json`。

## 数据和保留

```text
data/
├── state.sqlite
├── current_version.json
├── catalogs/
├── versions/<版本>/
└── outbox/<版本>/
```

`versions/<版本>/` 保存版本化角色数据、卡片和 manifest；正常运行不会自动删除已发布历史版本。首次启动只建立基线，不向 outbox 放入全量历史图。Bot 成功分发某版本的整批图片后清理对应 outbox；失败时保留以供重试。

后续版本会比较同一角色 ID 的规范化 JSON 全字段：信息有变化就重渲角色图鉴卡，并在 manifest 记录 `updated_characters_count`；变化角色不会进入 Bot outbox，只有新增角色才分发到群。

## 与 QQ bot 的交接

Bot 的 `[watch].outbox_dir` 指向服务端 `data/outbox`；`character_data` 和 `versions_dir` 指向本服务输出。双方通常位于同一主机/用户下，通过共享文件系统交接；服务端没有对 bot 的 HTTP API。

Manifest 包含版本、生成时间以及角色 `{id, name, file_name}` 列表。修改字段或清理时机时，必须同时更新 `xl_qqbot` 说明和双方契约测试。

## 故障定位

- `systemctl --user status ...` / `journalctl --user -u ...`：启动与调度错误。
- `run_server.py --once`：单次执行结果及失败阶段。
- `data/versions/<版本>/manifest.json`：Lua 解析、角色统计、卡片成功/警告/失败和下载摘要。
- renderer 错误：核实 `node --version`、`renderer/node_modules`、Cairo/Pango 和字体；Python 测试不能代替真实渲染。
- Lua 解码错误：核对 Java 21、unluac 和 opcode map 是否匹配。

日志和 manifest 可能含个人路径或资源名，对外分享前先脱敏。
