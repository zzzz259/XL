# 星落 · 抽卡手记（本地应用）

Windows 64 位便携应用，双击 StarfallGacha.exe 后自动打开默认浏览器。程序只监听 127.0.0.1，查询由本机程序访问官方游戏服务，没有开发者云端接口、上传、统计脚本或外部 CDN。

[完整用户指南](../docs/gacha-user-guide.md) · [构建与测试](../docs/gacha-development.md) · [数据协议](../docs/gacha-architecture.md)

## 使用

1. 完整解压应用文件夹到可写目录，再双击 StarfallGacha.exe。无需安装 Python 或其他依赖；不要单独移动 EXE，它依赖旁边的 _internal 文件夹。
2. 原有记录可直接使用页面的“导入记录”，支持 CSV、单账号 JSON 和全部账号 JSON 备份。
   现在可点击“官网登录并查询”：程序打开专用 Edge / Chrome 窗口，完成官网短信或 TapTap 登录后，自动获取凭据、查询并按账号身份归档，无需 F12。手动粘贴保留为备用方式。
3. 获取新记录：自行在官方门户登录，F12 → Application（应用）→ Local Storage（本地存储）→ https://i.haoplay.com.cn，复制 jwt 的 Value 或 HP_2070021 / HP_2070023 的完整 JSON 值。页面包含完整教程。
4. 官网认证、游戏 TCP 网关和专用官网登录窗口全部直接连接，不读取系统或环境 HTTP 代理，不需要开启代理工具。浏览存档、导入导出和生成长图可以离线使用。
5. 使用启动窗口重新打开浏览器、打开存档目录或退出程序。关闭浏览器不会停止程序；关闭启动窗口会停止本机服务。

程序重启会恢复上次打开的账号。重复启动同一目录的程序会打开已有页面；端口占用时自动选择空闲端口，存档不依赖端口或浏览器。

## 浏览器兼容与启动自检

启动器在后台检查登录浏览器、存档目录写入权限、回环端口、官网登录及游戏认证连接。网页「浏览器与环境检查」可重新运行，并查看逐项结果。网络检查不发送账号和凭据。

自动登录浏览器会从 Windows 注册表（当前用户/系统、32/64 位 App Paths）、PATH、常见安装目录查找 Edge / Chrome；也支持 PATH 中的 Chromium / Brave。网页可指定已有的兼容 Chromium 浏览器 exe 完整路径，留空恢复自动检测。开发运行还支持 STARFALL_BROWSER_PATH 环境变量。不支持自动控制 Firefox 的登录页面，但它仍可浏览本工具和手动粘贴凭据。

首选浏览器无法启动或调试接口未就绪时，会自动尝试下一个可用浏览器，Edge 和 Chrome 可互为备用；不同浏览器使用独立配置目录，避免相互修改登录会话。进程状态和调试接口健康分开判断；短暂断连会重试，进程仍在但接口持续不可达时显示连接故障。

本机诊断日志为 user-data/diagnostics/browser.jsonl，最多约 1 MB 并保留一份轮转文件。仅记录浏览器名称、尝试次数、健康状态及固定错误码，不记录凭据、手机号、网页内容或网络响应。自定义路径保存于 user-data/browser-settings.json。

## 本地多账号存档

- 默认存储：EXE 旁的 user-data/history.sqlite3。instance.json 仅用于定位当前运行实例。
- 当前查询协议每个登录身份对应一个游戏角色，按官网 UID + 登录渠道归档。查询不会按当前选中的存档写入其他账号，也不把未经游戏服务验证的角色包装字段当成身份。
- 同账号查询合并可见历史并去重，不删除之前已保存的旧记录。十连里的同名角色重复掉落会保留。同一条历史出现冲突内容时拒绝合并。
- 支持切换、改名、删除账号存档。删除仅影响本机，不影响游戏账号；请先备份重要记录。
- 更新应用时保留 user-data 文件夹，或先备份全部账号。更换电脑可使用 JSON 备份恢复；更换浏览器不影响存档。
- 登录凭据只在查询内存中使用，不保存到数据库、配置或日志。JSON / CSV 包含存档名称与账号 UID、渠道，分享前可自行检查；不含登录凭据或设备 ID。
  自动登录默认使用临时浏览器配置，结束后清理；浏览器运行期间会写入临时会话文件。勾选“在本机记住官网登录状态”后，会话保存在 user-data/login-profiles 中，可复用或从页面删除；它包含官网登录信息，不能当成普通抽卡备份分享。登录失效仍需重新完成官网验证，不进行独立续期。

## 导入导出

- JSON：单账号完整导出，或“备份全部”包含所有账号。含稳定存档标识，导入后自动匹配并合并；全部备份使用“自动识别”导入。
- CSV：兼容早期九列导出。新格式额外保留卡池 ID、存档 ID、名称、UID、渠道、卡池分类，便于往返导入。
- 旧文件没有账号身份时默认新建独立存档，用户明确选择目标后才合并。旧 CSV 的重名卡池缺少 ID 时保守处理，UP 未知不伪装成歪或 UP；它与后续实时查询可能无法完全匹配，请优先使用 JSON 备份保留信息。
- 文件最多 30 MB，每个账号最多 10 万条历史、100 万抽。全部备份最多 500 个账号；整批事务处理，格式错误或冲突时不会部分写入。
- 长图：导出当前卡池分类的生涯统计、五星间隔与卡池记录，最新在前。超过安全高度自动分张，可逐张下载 PNG 或一次下载整组 ZIP；最多 100 张，更大的记录请按分类拆分。
- 所有导出在浏览器内生成；网页不把文件传给云端。导入仅把内容传给同机回环服务并写入本机数据库。

## 游戏配置自动更新

「游戏配置」中可填写部署者提供的 HTTPS `/current.json` 地址。启动时后台检查配置，成功后 6 小时内不重复下载，也可手动检查。只下载小型角色/卡池 JSON；不上传用户记录、账号或凭据，不下载执行代码。哈希、大小、格式或版本校验失败时继续使用本机配置，旧存档会在打开时按新配置重新识别名称、星级和卡池规则。

当前发行包尚无公网更新源，首次需在「配置下载地址」填入自己服务器发布的地址。开发者可修改 `data/update-source.json` 后重新构建以预设地址。缓存位于 `user-data/catalog-cache`，更新应用时与其他存档一起保留。本功能更新游戏配置；程序逻辑升级仍需安装新 EXE/APK。

## 统计口径

普通、限定、典藏独立统计，启程单独计数。内置基线来自游戏 Lua 版本 134359843258232660，运行时以已验证配置为准。UP 依据对应卡池的当期角色配置，大小保底只根据连续可见历史推断。

计算按时间、序号和服务端掉落顺序正序进行，展示按最新优先。首个可见五星、断档后的间隔以“≥”显示；十连内真实逐抽顺序尚未独立核验。累计存档不保证覆盖全部生涯，保底推断不代表官方实时状态。

平均抽数＝本分类的可见总抽数÷五星数量，包含首个五星及当前垫抽；无五星时显示「—」。不再只取前序完整的五星间隔做平均。同一保底组的服务端记录序号 80→1 为连续循环，不会清空垫抽或保底推断；真正跳号仍按断档处理。升级后打开旧存档、备份全部时自动重算统计，无需重新登录查询。

## 开发与构建

开发环境 Python 3.11+，运行仅使用标准库：

    .\start.ps1
    # 或
    python -B desktop.py
    # 无启动窗口的开发预览
    python -B app.py --port 8788 --data-dir <本机测试数据目录>

启动器优先使用当前项目 .venv 或仓库已有 .venv。构建环境另需 PyInstaller；使用项目环境，不安装到全局。

    python -B -m unittest discover -s tests -v
    node --test tests/image-export.test.cjs
    python -B scripts/build_portable.py --output <构建输出目录>

构建脚本生成运行产物 ZIP，排除个人存档、预览文件、测试与源码；ZIP 中只有一个应用目录。此应用需要本机运行，不能作为 TapTap 静态网页包启动。

程序提供精确 Host/Origin 检查、请求体限制、查询限流、两项并发查询和静态文件白名单。不向外网监听，不接受任意网关地址。游戏服认证及只读历史查询复用已验证的 TCP/protobuf 实现。凭据本身仍是账号登录权限，不是官方抽卡专用只读密钥。

设计预览可用 app.py --preview-report <报告JSON> 配合 /?preview=1；该数据不自动存入账号库。static/demo.json 为虚构示例，不保存为个人账号。

## Windows 一键构建（源码发行包）

需要 Windows x64、Python 3.11+ 和网络访问 PyPI（仅构建机需要）。在项目根目录运行：

    powershell -ExecutionPolicy Bypass -File .\scripts\build_windows.ps1

该脚本会在 `.venv` 安装 PyInstaller，先执行 Python / JavaScript 测试，再构建 `output\星落抽卡手记-本地版.zip`。**普通玩家只需要这个最终 ZIP，不必安装 Python。**

也可以在本 monorepo 根目录的 GitHub 仓库打开 **Actions → Build Windows portable app → Run workflow**，在该次运行的 **Artifacts** 中下载 `StarfallGacha-Windows-x64`。这个方式由 GitHub 的 Windows 构建机完成，不需要在自己的电脑安装 Python。切勿把 `user-data`、登录凭据或浏览器登录配置提交到仓库。

Windows 本机用户还可以在解压后的项目文件夹中直接双击 `build_windows.bat`，效果相同。若 PC 没有 Python 或不希望在本机安装构建工具，推荐使用上述 GitHub Actions。
