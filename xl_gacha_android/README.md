# 星落抽卡手记 · Android

本地 Android 应用，复用电脑端页面、角色和卡池配置。支持 Android 9 及以上，建议使用新版 Android System WebView。无需 Python、浏览器扩展或存储权限。

[完整用户指南](../docs/gacha-user-guide.md) · [通用构建与测试](../docs/gacha-development.md) · [数据协议](../docs/gacha-architecture.md)

## 使用

1. 安装 APK，打开应用，点击「官网登录并查询」。
2. 在显示 `https://i.haoplay.com.cn` 的独立官网页面正常登录。短信验证码、隐私协议和 TapTap 授权由用户本人完成。
3. 应用识别登录状态后自动查询，将抽卡记录按账号身份合并到本机。也可展开手动凭据输入，粘贴自己取得的 JWT 或 HP 对象。
4. 在「本地存档」切换账号；JSON/CSV 可导入导出，全部账号可备份为一个 JSON。电脑端导出的 JSON 也可导入。
5. 点击「长图」，生成后选择 PNG 或 ZIP 保存。Android 10 及以上保存到「下载/Starfall」，Android 9 使用系统文件选择器。

默认不保留官网会话；勾选「记住登录」只保留最近一次会话。更换登录会话可能清理旧会话，但不会清除抽卡存档。TapTap 跳转及登录兼容性取决于手机 WebView 和官方页面。

记录存于应用的 IndexedDB，更新同签名应用时保留。卸载应用、清除应用数据会删除记录；换手机前请导出 JSON，再在新手机导入。没有开发者云端或账号同步服务。查询仍需联网到游戏服务；这里只展示官方返回并累计保存的历史，不保证包含全部生涯。

0.2.1 同步修复记录序号 80→1 被当成断档的问题，保留真实垫抽和跨池继承；平均抽数改为本分类可见总抽数÷五星数量，包含首个五星和当前垫抽。覆盖安装后自动重算已有存档，不需要重新查询。

0.3.1 修复系统保存产生0字节文件的问题，并在新登录时清空实际官网页面的旧存储，增加「登录其他账号」，第二账号登录已由用户复测确认。0.3.2 补充 TapTap → QQ 的协议与可信授权页连续跳转处理，但QQ授权后的HTTPS回跳仍可能进入外部浏览器，完整链路尚未通过。[0.2～0.3.2 更新公告](../docs/releases/gacha-v0.3.2.md)

游戏认证 HTTPS 和游戏网关 TCP 使用直接连接，不读取系统 HTTP 代理。官方登录 WebView 遵循 Android 的网络设置；应用不会绕过系统 VPN。

## 实现边界

0.3.0 新增公共游戏配置更新。后续修订已内置正式 HTTPS 配置地址，可在「游戏配置 → 配置下载地址」修改；客户端只下载和校验 JSON，不上传账号与记录。启动后台检查及手动刷新均可；失败继续使用内置/已验证缓存，旧存档按新配置重新识别。

- 主页面只加载 APK 内置资源，入口为固定 HTTPS 本地域名；原生桥只注入本地页面。
- 官网使用独立 WebView，不注入原生桥；仅在严格匹配的官网 HTTPS 来源读取白名单登录字段，不读取手机号等无关存储。
- JWT 仅供本次查询使用，不写入抽卡存档、导出文件或日志。选择记住登录会保留官网 WebView 自身的登录状态。
- 游戏认证地址和网关受固定域名约束，TLS 使用系统信任验证，不忽略证书错误。
- 原生 Java 实现已验证的游戏协议，JavaScript 在本机解析、合并并计算统计。角色与卡池映射来自电脑端配置，配置 JSON 可独立更新，程序逻辑仍需同签名 APK 覆盖升级。

## 构建

需要项目 Python 环境与 Pillow、Node、JDK17+、SDK API35/build-tools35，支持标准 Linux/Windows SDK 和旧离线布局。通用命令及真实 Android JSON 测试见[构建指南](../docs/gacha-development.md)。正式包显式提供 Git 外原签名密钥；开发包显式选择 --development-key，不能冒充正式升级。applicationId 保持 cn.starfall.gacha.local；原密钥、密码和证书指纹需离线备份。
