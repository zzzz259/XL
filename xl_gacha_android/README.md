# 星落抽卡手记 · Android

本地 Android 应用，复用电脑端的角色、卡池配置与共享脚本，主页面为独立的移动端界面。支持 Android 9 及以上，建议使用新版 Android System WebView。无需 Python 或浏览器扩展；Android 10 及以上保存本应用生成的图片无需相册读取权限，Android 9 保存到相册时需要存储写入权限。

[完整用户指南](../docs/gacha-user-guide.md) · [通用构建与测试](../docs/gacha-development.md) · [数据协议](../docs/gacha-architecture.md)

## 使用

1. 安装 APK，打开应用：没有本机存档时直接进入「查询」，已有存档时进入「记录」。在「记录」空状态点击「查询我的记录」，或在「我的」点击「登录并更新记录」。
2. 在「查询」页选择渠道：官服网页登录、TapTap App 授权，或构建启用的「B 服授权」；官服在显示 `https://i.haoplay.com.cn` 的独立官网页面正常登录。短信验证码、隐私协议和 TapTap 授权由用户本人完成。
3. 应用识别登录状态后自动查询，登录与查询进度在「查询」页内展示，完成后跳到「记录」，记录按账号身份合并到本机。也可在「查询」页展开「手动凭据」，粘贴自己取得的 JWT 或 HP 对象。
4. 点击顶部的账号名打开账号切换；在「我的」的当前存档卡片改名或删除。JSON/CSV 在「我的」导入导出，全部账号可备份为一个 JSON。电脑端导出的 JSON 也可导入。
5. 在「记录」点击右下浮动的「分享」生成抽卡长图，或从「我的 → 长图与分享」进入；选择图片后「保存所选」或「分享所选」，也可逐张操作。图片保存在相册的「星落抽卡手记」，分享通过系统面板交给已安装的 QQ、微信等接收应用；图片数量与画质由接收应用处理。ZIP/JSON/CSV 仍保存到「下载/Starfall」（Android 10+）或系统文件选择器（Android 9）。

0.4 查询页不再提供「保留官网会话」：每次发起登录都固定开启新的官网会话（不保留旧登录状态、不保存密码，也不写入抽卡存档）；会话保留能力仍保留在原生实现中，仅界面不提供。TapTap 跳转及登录兼容性取决于手机 WebView 和官方页面。

记录存于应用的 IndexedDB，更新同签名应用时保留。卸载应用、清除应用数据会删除记录；换手机前请导出 JSON，再在新手机导入。没有开发者云端或账号同步服务。查询仍需联网到游戏服务；这里只展示官方返回并累计保存的历史，不保证包含全部生涯。

0.2.1 同步修复记录序号 80→1 被当成断档的问题，保留真实垫抽和跨池继承；平均抽数改为本分类可见总抽数÷五星数量，包含首个五星和当前垫抽。覆盖安装后自动重算已有存档，不需要重新查询。

当前版本 **0.4**（versionCode 15）。0.4 将主页面更换为移动端专用界面：底部「记录、查询、我的」三栏。「记录」自上而下连续展示当前账号与总抽数、抽卡生涯（普通、限定、典藏三类垫抽以简行并入生涯卡，不再有独立的当前垫抽区块），卡池按普通、限定、典藏、启程分类，默认展开五星间隔，角色收获可继续展开，星级与卡池分布、原始招募明细折叠在页面底部，搜索、筛选与分页在明细内完成，右下浮动「更新」与「分享」；「记录」统一为简洁布局（body 固定 compact-ui，无「简洁/详细」切换，也不读写 localStorage 界面偏好），卡片、行距与边距更紧凑，五星间隔条降到约 24px，次要信息——每条五星的时间与本池第几抽、账号更新时间、卡池尾部次要说明、覆盖说明及各标题旁的 eyebrow 与次要文字——一律隐藏，统计与原始数据不变；「查询」把官服网页登录、TapTap App 授权、构建启用的 B 服授权和手动凭据直接做在页内，查询进度也在页内展示，不再使用登录对话框，也不再提供「保留官网会话」（每次登录固定新会话）；宣传副标题、「从这里开始」引导、只读说明、查看演示按钮及 TapTap/B 服诊断复制入口均已从界面移除，`demo.json` 仅作为合成测试数据，渠道入口、导入与手动凭据保留；「我的」集中账号切换、改名、删除，登录并更新、导入、JSON/CSV 导出、备份全部账号、长图、配置下载地址、最近查询回执与统计、隐私说明。栏间导航记录访问顺序和每栏滚动位置，返回先回上一栏并恢复其位置；后台配置刷新按新配置重算时保留当前筛选与浏览位置。结果页头像一律用名称首字加星级色块占位，UP 角色 ID 从已内置校验的 catalog 补充，不联网取图、不伪造真实头像，也不做账号级欧非鉴定、累计消耗金额或实时概率展示。APK 内置独立的 `web/index.html`、`mobile-ui.css` 与 `mobile-app` 系列脚本及 `mobile-navigation.js`，不再打包电脑端旧版桌面 `index/app/style/theme/local/login/catalog-ui/environment`；IndexedDB 存档、受约束原生桥、LongImage 长图算法与官服、TapTap App、B 服、手动凭据登录全部保留。0.3.6 在完整 0.3.4 基线上接入 B 服授权查询与 TapTap App 授权，见 [0.3.4 之后的更新公告](../docs/releases/gacha-v0.3.6.md) · [渠道登录实现](../docs/gacha-channel-login.md)。电脑端停止维护，后续只交付 Android。

官服可在「查询」页选择「TapTap App 授权」，在官网阅读协议并选择 TapTap，随后点击手记登录窗口上方的「打开 TapTap App」。在已登录的官方 TapTap 确认后，通过系统最近任务返回手记，在原网页完成官网授权，随后自动查询。无需手动扫描二维码；官方确认均保留。取消、授权过期或未安装 TapTap 时可重试或继续网页登录；0.4 界面不再提供 TapTap 诊断复制入口（脱敏诊断能力仍保留在原生实现中），反馈时不发送密码或令牌。当前仅验证国内 TapTap，尚未验证国际版。

游戏认证 HTTPS 和游戏网关 TCP 使用直接连接，不读取系统 HTTP 代理。官方登录 WebView 遵循 Android 的网络设置；应用不会绕过系统 VPN。

## 实现边界

0.3.0 新增公共游戏配置更新。后续修订已内置正式 HTTPS 配置地址，可在「我的 → 游戏配置 → 配置下载地址」修改；客户端只下载和校验 JSON，不上传账号与记录。启动后台检查及手动刷新均可；失败继续使用内置/已验证缓存，旧存档按新配置重新识别。

- 主页面只加载 APK 内置资源，入口为固定 HTTPS 本地域名；原生桥只注入本地页面。
- 官网使用独立 WebView，不注入原生桥；仅在严格匹配的官网 HTTPS 来源读取白名单登录字段，不读取手机号等无关存储。
- JWT 仅供本次查询使用，不写入抽卡存档、导出文件或日志。0.4 界面不提供「保留官网会话」：每次登录固定新建官网会话、不保留官网 WebView 的登录状态，不保存密码（会话保留能力仍保留在原生实现中）。
- 分享入口只接受 `accounts.taptap.cn/social/callback/qq` 的 HTTPS 链接，参数仅含单个 `code`/`state`，且 `state` 必须匹配当前授权页面观察到的值。回调仅在内存中处理，超时、取消、换会话、重复使用或窗口不存在时拒绝，不创建新登录来消费旧回调。
- 长图分享使用独立私有 PNG 缓存和仅临时授权读取的 ContentProvider，不暴露存档、配置或登录目录。分享不生成相册/下载副本；临时图片在 24 小时后过期，在下次启动或准备分享时清理，总缓存上限 128 MiB。打开分享面板不表示消息已经发送。
- 游戏认证地址和网关受固定域名约束，TLS 使用系统信任验证，不忽略证书错误。
- 原生 Java 实现已验证的游戏协议，JavaScript 在本机解析、合并并计算统计。角色与卡池映射来自电脑端配置，配置 JSON 可独立更新，程序逻辑仍需同签名 APK 覆盖升级。

## 构建

需要项目 Python 环境与 Pillow、Node、JDK17+、SDK API35/build-tools35，支持标准 Linux/Windows SDK 和旧离线布局。通用命令及真实 Android JSON 测试见[构建指南](../docs/gacha-development.md)。正式包显式提供 Git 外原签名密钥；开发包显式选择 --development-key，不能冒充正式升级。applicationId 保持 cn.starfall.gacha.local；原密钥、密码和证书指纹需离线备份。

B 服授权实现保留在代码中；入口由 APK 内 `build-info.json` 的 `bilibili_enabled` 控制，仅在构建时提供 Git 外 `--bilibili-config` 才写入并显示。普通 QA 构建未提供该私有配置，故不显示入口，并非功能缺失；配置含客户端 SDK 接入参数，不放进仓库。0.4 正式包为 `cn.starfall.gacha.local` / versionCode 15，沿用正式 0.3.4 签名；默认文件名为 `星落抽卡手记-Android-v0.4.apk`。`--application-id`、`--label`、`--version-code`、`--version-name` 仍可生成独立 QA 包。此前 `cn.starfall.gacha.bilitest` 为独立测试应用，其存档需通过 JSON 迁移至正式包。APK 内 `build-info.json` 记录基线和实际 Java/Web 源码 SHA256，核对版本时同时核对来源。所有构建输出必须位于仓库外。
