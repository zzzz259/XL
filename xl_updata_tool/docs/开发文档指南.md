# XL Update Tool 开发文档指南

## 项目概述

XL Update Tool 是一个基于 PySide6 的桌面应用，用于下载和浏览游戏资源包。

### 功能特性

- 版本更新检测与下载
- 资源包全量/增量下载
- 资源包浏览与管理
- 下载进度实时显示
- 日志记录与错误追踪
- 自动导出资源到 material 目录
- 批量预览图片（使用 SpineViewerCLI 导出 .skel 为 PNG）
- 皮肤（Skin）导出：从 .skel 二进制提取 `motion_*` 名称，逐个导出各表情独立图片
- 角色图片预览（多选[Ctrl/Shift] + 拖放复制 + 自适应菜单[单选/多选/合成图] + 批量导出 + 导出参数对话框 + 配对合成 + 多动画导出）
- 合成图视频导出（SpineViewerCLI 直接导出 MP4 + FFmpeg colorkey 叠加合成）
- 预乘 Alpha（--pma）选项支持
- 音频管理器（自动 .bytes/.bank 后处理 + 音频播放 + 单选导出）
- 音频分类导出：语音按角色（中文/日语）+ 音乐按 `BaseSoundChapter` 专辑章节（星落/旅途/百折千回/危机四伏/旅途轶事）
- 导入AS 可配置导出：lua / 角色立绘 / FGUI图集 / 音频 四类勾选，按 Container 前缀严格区分
- Lua 成品按版本留存到 `output/lua/<版本时间戳>/`，导出成功后清理 `data/material/assets/lua/` 临时目录；音频最终产物增量写入 `output/audio/`，`data/material/assets/fmodassets/` 只作为短生命周期中间态
- Lua 导出后自动衔接角色解析：仅最新版本且包含 `BaseCard.lua`、`BaseWord_cn.lua` 时触发；角色数据按版本快照增量合并，并在角色界面显示未读“新”角标
- 版本备注 delta 显示：每个版本显示相对上一版本的「新增 / 移除 / 未变」
- 工具栏：顶部视图栏（版本列表/图片预览/音频/角色）+ 侧边功能栏（检查更新/导入AS/刷新/作者 + 导出配置）
- 界面视觉基线：蓝灰深色作为唯一正式主题，旧主题配置自动兼容迁移
- 页面壳层：图片、音频、角色页面统一页头、操作栏、危险操作、状态栏和空状态表达
- 版本工作区：版本列表增加工作区说明、版本数量、下载数量和当前选择摘要
- 角色 Wiki 详情：角色身份、属性、技能、成长消耗、故事和语音按区块展示，技能数字支持一键高亮
- 页面状态反馈：图片预览显示选择摘要，音频空目录显示下一步提示，播放状态使用稳定中文文本
- 对话框视觉收口：图片查看器、角色选择、导出设置和右键菜单统一使用蓝灰主题令牌

## 代码所有权与架构迁移

XL 已完成 P0-P8 功能域 ownership 与协作架构收口。`app/bootstrap`、`app/platform` 和 `app/shared` 提供稳定契约、装配、平台能力与共享 UI 入口；Audio、Characters、Versions、Importer 和 Preview 已完成各自功能域迁移。现有 `app/core`、`app/ui` 继续作为兼容层保留，不改变已有导出和运行目录契约。

功能域边界、公共文件规则和已完成阶段见[代码所有权与边界](代码所有权与边界.md)。后续普通 Feature 改动应集中在自己的功能域；修改 Shell、bootstrap、platform 或 shared 需要单独 Issue 和影响说明，并同步更新对应 worklog 与变更摘要。

`app.bootstrap.create_features()` 负责按注册顺序装配 Feature；当前 MainWindow 仍是兼容期 Shell，新增功能不得继续把业务状态和后台任务堆回主窗口。

### Audio Feature（P1）

- `app/features/audio/page.py`：`AudioPage` 自持标题、操作栏、音频树、播放控制和状态栏，只发出语义信号；不接收主窗口回调，也不返回控件字典。
- `app/features/audio/controller.py`：`AudioController` 持有列表/选择状态、播放器、右键菜单、导出和解密任务，消费 Page 信号并发布结果。
- `app/features/audio/service.py`：`AudioService` 是 Qt-free 的目录服务，负责 `output/audio/` 扫描缓存、`.audio_state.json` 快照、未读状态、选中导出和 `AudioCatalogIndex` 目录索引；索引为后台预热与按层级展开提供根目录、子目录和文件范围查询。
- `app/features/audio/tree.py`：负责首层目录、展开层级和叶节点构造，以及目录递归勾选、半选状态和未读标记向上聚合。
- `app/features/audio/worker.py`：提供目录预热 Worker 和功能域侧解密 Worker 入口；目录预热只执行扫描、快照和索引建立，不创建 Qt 控件。
- `app/ui/main_window.py` 当前只做迁移期适配：接收 AudioController 的任务结果并参与导入总流程，不持有播放器、选择状态或 AudioDecryptWorker。
- `app/ui/views/audio_view.py` 与 `app/ui/features/audio_controller.py` 继续作为兼容入口，调用方切换完成并通过用户验证后再删除。

### Characters Feature（P2）

- `app/features/characters/page.py`：`CharacterPage` 自持页头、解析/刷新/已读/CSV 操作、角色表格、Wiki 详情和空状态，只发出语义信号。
- `app/features/characters/service.py`：Qt-free 门面，负责角色仓库/旧缓存恢复、最新 Lua 目录与 Base 文件判断、解析调用、版本快照合并、未读和 CSV。
- `app/features/characters/controller.py`：协调页面状态、筛选、详情选择、查看后清除未读、手动解析，以及 Lua 导出后的自动解析进度。
- `app/ui/main_window.py` 只负责角色页面导航、显隐和导入结果接入；不直接导入角色解析器、仓库、缓存或 Wiki 模型。
- `app/ui/views/character_view.py` 保留为迁移期兼容工厂，旧调用方可取得旧控件映射，但新页面不再通过 `parent._xxx` 回调或 `controls_dict` 管理行为。

### Versions Feature（P3）

- `app/features/versions/page.py`：`VersionPage` 自持版本工作区页头、统计摘要和版本表格，通过语义信号向控制器报告行点击、选择和悬停。
- `app/features/versions/service.py`：`VersionService` 集中封装版本仓库、版本差异、增量/全量下载目标、磁盘 Bundle 状态校准、更新注册和已下载清理，不依赖 Qt。
- `app/features/versions/controller.py`：协调表格渲染、单选/Ctrl 多选、更新检查线程、下载线程、进度和删除确认。
- `app/features/versions/worker.py`：提供功能域侧下载 Worker 入口，当前包装迁移期 `ui/workers/download.py`，保持网络、校验和进度信号契约。
- `app/ui/main_window.py` 只保留版本页面显隐、全局进度条和导入流程读取当前选中版本的适配，不持有版本表格状态或下载 Worker。

## 核心模块说明

### core/downloader.py 与 ui/workers/download.py

下载逻辑按依赖方向拆成两层：

- `app/core/downloader.py`：无 Qt 的 HTTP 请求、版本信息获取、Bundle 校验函数；
- `app/ui/workers/download.py`：`CheckUpdateThread` 和 `DownloadWorker` 的 Qt 生命周期、进度信号和错误信号。

`DownloadWorker` 保持原有信号兼容：`progress`、`item_done`、`item_skip`、`item_fail`、`all_done`、`error`；网络失败和 MD5 不匹配最多重试 3 次。下载数据先写入同目录临时文件，修复成功后再原子替换最终 Bundle，失败不会覆盖已有可用文件。

### core/database.py

SQLite 数据库管理，存储版本信息和资源包路径。

### core/logger.py

日志会话和处理器配置。`main.py` 先通过 `runtime_config.py` 解析运行模式，再调用
`configure_logging()`，因此 `--debug` 会在导入主窗口和业务模块前生效。

- 每次启动创建 `logs/<session_id>/` 会话目录。
- `app.log` 记录 INFO 及以上，`error.log` 记录 WARNING 及以上。
- Debug 模式额外生成 `debug.log`，包含 DEBUG 级别和外部程序诊断摘要；普通模式控制台和文件都不接收 DEBUG。
- 每条日志包含毫秒时间、组件、task_id 和 stage；旧调用方继续使用 `from app.core.logger import logger`。
- 文件日志不可用时仍保留控制台处理器，并输出降级信息。

### 诊断上下文与外部进程

- `task_context.py` 的 `task_operation()` 为导入、Lua 和音频 Worker 绑定可搜索的任务 ID；`stage_operation()` 为导入/音频阶段绑定 component/stage。
- `process_runner.py` 保持 `subprocess.run()` 的返回契约，Debug 日志记录工具、参数、工作目录、退出码、耗时和输出字节数，失败时记录 stdout/stderr 尾部。
- `environment.py` 在 Debug 启动时写入 `logs/<session_id>/environment.txt`，包含 Python、平台、路径、Git 提交、依赖和工具可用性。
- `crash_reporter.py` 注册顶层和线程异常钩子，报告写入同一会话目录。当前 UI 布局标识、Debug 数据目录隔离和失败 staging 保留属于后续任务。

### core/character_loader.py

角色 Lua 数据解析引擎（无 Qt 依赖，纯模块级函数）。从指定版本的 `output/lua/<版本>/` 解密后的 Lua 文件中提取结构化角色数据，供 Characters Feature 的 `CharacterService` 调用。主要函数：
- `parse_word_file(file_path)` - 解析 `BaseWord_cn.lua` 文本映射（id → 文本）
- `parse_cv_file(file_path)` - 解析配音 `BaseCvNameCn.lua`
- `parse_level_up_file(file_path)` - 解析 `BaseCardLevelUp.lua` 升级属性
- `parse_quality_up_file_with_cost(file_path)` / `parse_skill_level_up_file_with_cost(file_path)` - 解析品质/技能升级消耗
- `parse_badge_suit_file(file_path, word_dict)` / `parse_item_file(file_path, word_dict)` - 解析套装与物品
- `parse_basecard_file(file_path, word_dict, cv_dict, level_up_dict, quality_up_dict, skill_file_path, skill_level_up_file_path, badge_suit_dict)` - 完整解析 `BaseCard.lua`，返回角色数据字典
- 技能/突破相关：`extract_skill_info`、`extract_awakening_skill_info`、`extract_awakening_info`、`extract_multi_level_skill_info_new`、`get_breakthrough_cost`、`get_normal_skill_upgrade_cost`、`get_passive_skill_upgrade_cost`
- 块提取与 T() 引用解析：`extract_all_card_blocks`、`extract_t_references`、`parse_t_args`、`resolve_t_call`、`parse_t_function_params`、`process_t_function_params`、`merge_t_function_params`
- `load_character_data(lua_dir, progress_callback=None)` - 角色数据整体加载（纯解析入口），解析全部 Lua 文件并返回 `(characters, characters_full, word_map)`

### 调用关系（第二轮重构后）

`_load_character_data` 保留在 `MainWindow` 中作为 UI 协调层，职责：
- 管理进度条和状态栏更新
- 调用 `app.core.character_loader.load_character_data` 执行实际解析
- 将解析结果赋值给 `self.characters`、`self.characters_full`、`self.word_map`
- 调用 `_populate_character_table` 刷新表格

**解析逻辑**：`app/core/character_loader.py`（无 Qt 依赖，可独立测试）

**调用链路**（`output/` 为最终产物与角色数据仓库）：
用户点击【角色】或【开始解析】
↓
`_load_character_data()` ← UI 协调层（选择最新版本目录，绝不读 `data/material/assets/lua`）
↓
先读 `output/character_data/characters_repository.json`；当前版本已解析时直接恢复，手动刷新才重解析
↓
`character_loader.load_character_data(output/lua/<版本>)` ← 纯解析引擎（模块函数）
↓
返回 `(characters, characters_full, word_map)`；`character_repository.merge_snapshot()` 保存 `versions/<版本>.json`，并计算 new/changed 未读状态
↓
由 `CharacterController` 从当前合并数据派生表格索引，更新 Page（进度、表格、右侧详情）；打开角色详情后清除该角色未读角标

> 说明：AS 导入时 `ImportASWorker` 先在 staging 中反编译，再把 `.lua` 成品发布到 `output/lua/<版本>/`；成功后清理 `data/material/assets/lua/`。非最新版本或缺少必要 Base 文件的 Lua 只留存，不自动更新角色数据。旧版 `LuaDecryptWorker`（unluac 回退解密）已从 `MainWindow` 移除。

### core/lua_repository.py 与 core/character_repository.py

- `lua_repository.py`：负责版本目录命名、列出最新 Lua 版本、检查角色解析所需 Base 文件、原子发布 `.lua` 成品和清理 `data/material/assets/lua/`。

## 资源浏览流程

> **v1.21.0 更新**：导入AS 已集成到主界面，不再弹出独立的资源浏览器窗口。
> 所有操作（修复、解析、导出分类）在主界面后台执行，进度通过下载进度条和状态栏显示。

点击"导入AS"后，执行以下流程（全部在 `ImportASWorker` 后台线程中执行，不阻塞 UI）：

1. **获取版本文件列表**：
   - 从数据库获取选中版本的所有 Bundle 本地路径
   - 如果文件列表为空，提示"此版本没有已下载的 bundle，请先下载"
2. **阶段 1：修复文件头**（`_stage_fix`）：
   - 直接对原始 `.bundle` 文件调用 `fix_bundle_inplace`（不再复制到 `_as_temp`）
   - 实时更新进度条："修复文件头: X/总数"
   - 单个文件修复失败时记录日志并跳过，不中断整体流程；只有 `fix_bundle_inplace()` 明确返回成功才计入成功数
   - 如果所有文件修复失败，提示"所有文件修复失败，请删除该版本并重新下载"
3. **阶段 2：解析资源**（`_stage_map`）：
   - 调用 AssetStudio CLI 生成资源映射（`--map_op Both --map_type JSON`）
   - 实时更新进度条："解析资源: X/总数"
   - 输出 `assets_map.json` 到 `data/bundles/{ts}/_map/`
4. **阶段 3：导出分类**（`_stage_export`）：
   - 先写入 `data/.xl-import-*/material/` 临时目录，全部分类成功后再替换 `data/material/` 对应分类
   - 按「侧边栏勾选的分类」（lua / 角色立绘 / FGUI图集 / 音频）逐个调用 AssetStudio CLI 导出，每类用 `--types` + `--containers` 严格匹配（见 `EXPORT_CATEGORIES` 常量）
   - 实时更新进度条："导出分类: X/分类总数"
   - 若导出了 lua 分类，在临时目录中反编译 `.lua.bytes → .lua`，提交成功后再同步到 `output/lua/`
   - 清理 `.prefab` 后缀（AssetStudio CLI 可能错误添加）
   - 统计导出文件总数；AssetStudio 局部资源报错但目标分类已有产物时允许提交并记录警告，分类完全无产物或任务取消时清理临时目录并保留旧产物
5. **完成提示**：
   - 成功：弹窗"导入完成！文件已分类到 data/material/（共 N 个文件）"
   - 失败：弹窗"文件可能损坏，请点击【删除已下载】并重新下载"

## 图片预览与导出流程

### 图片预览流程

点击【图片预览】按钮后：

1. **切换视图**：整体隐藏版本工作区，显示图片预览视图；版本页的标题、表格和外层页面同步退出布局，避免在当前页面上方留下空白占位
2. **缓存检查**：检查 `output/character/` 目录是否已有 PNG 图片
   - 已有图片：直接加载（日志：`预览目录已存在 X 张图片，直接加载`，状态栏显示 `来源：缓存`）
   - 无图片：启动后台导出线程后加载（状态栏显示 `来源：刚导出`）
3. **图片导出**（`PreviewExportWorker` 后台线程）：
   - 在后台线程执行，不阻塞 UI（进度条实时反馈 `导出中... X/总数`）
   - 扫描 `data/material/` 目录中的 `.skel` 文件
   - **去重优化**：`force=False` 时，若 `output/character/{base_name}.png` 已存在且大小 > 0，则跳过该文件
   - **强制刷新**：点击【🔄 重新加载图片】时清空目录并 `force=True` 重新导出
   - 对每个 `.skel` 执行以下两步导出：
     - **动画帧导出**（`export_animation_frames`，位于 `adapters/spine_adapter.py`）：
       - 从 `.skel` 二进制文件提取动画名称（正则 `motion_[a-zA-Z0-9_]+`）
       - 遍历每个动画，使用 SpineViewerCLI 导出第一帧 PNG
       - 命令：`export -f Png --time 0 --duration 1 --fps 1 --scale 4 --max-resolution 8192 --pma`
       - 支持 `--pma` fallback：带 `--pma` 失败时自动重试不带 `--pma`
     - **皮肤图片导出**（`export_skel_skins`，位于 `adapters/spine_adapter.py`）：
       - 从 `.skel` 二进制文件提取 `motion_*` 名称作为皮肤列表
       - 遍历每个皮肤，使用 SpineViewerCLI 导出独立 PNG
       - 动画固定为 `idle`，添加 `--skins {skin_name}` 参数
       - 输出文件名：`{base_name}_{skin_name}.png`
       - 支持 `--pma` fallback
   - **配对合成**：识别 `xxx.skel + xxx_bg.skel` 配对，合成 `{xxx}_composite.png`（去重：已存在则跳过）
   - 信号：`progress(int, int)` / `export_finished(bool, str)` / `error(str)`
   - 支持取消：切换视图时调用 `cancel()` 终止后台任务
4. **缩略图显示**：网格展示，支持 Ctrl/Shift 多选、拖放复制

### 视频导出流程

#### 普通视频导出（`_export_with_dialog`）

1. 弹出 `ExportSettingsDialog` 对话框
2. 用户选择：格式（MP4/GIF）、动画、时长、帧率、缩放、预乘 Alpha
3. 从 PNG 文件名提取皮肤名（`motion_*`），如有则添加 `--skins` 参数
4. 构建 SpineViewerCLI 命令：
   ```
   SpineViewerCLI.exe export <skel> -f Mp4/Gif -o <output> -a <animation>
     --atlas <atlas> --duration <dur> --fps <fps> --scale <scale>
     [--pma] [--skins <skin_name>]
   ```
5. 输出到 `output/video/`（MP4）或 `output/character/`（GIF）

#### 合成图视频导出（`_export_composite_video`）

采用 **分别导出角色和背景 MP4 → FFmpeg 叠加合成** 的方案：

1. 从合成图文件名（如 `xxx_composite.png`）解析基础名 `xxx`
2. 在 `self._skel_map` 中查找 `xxx.skel`（角色）和 `xxx_bg.skel`（背景）
3. 弹出 `ExportSettingsDialog` 对话框获取参数
4. 调用 `_export_composite_video_with_params` 执行：
   - **步骤 1**：导出角色 MP4（`role_temp.mp4`）
     - 使用 SpineViewerCLI `export -f Mp4`，添加 `--color "#00000000"` 透明背景
     - 根据 `skin_name` 参数决定是否添加 `--skins`
   - **步骤 2**：导出背景 MP4（`bg_temp.mp4`）
     - 不应用皮肤参数
   - **步骤 3**：FFmpeg 叠加合成
     - 调用 `ffmpeg_composite_videos` 函数（位于 `adapters/spine_adapter.py`）
     - FFmpeg 路径通过 `get_ffmpeg_path()` 获取（`adapters/spine_adapter.py`，优先 `tools/SpineViewer/ffmpeg.exe`）
     - MP4 滤镜：`colorkey=0x000000:0.1:0.2`（去除角色视频黑色背景）
     - 完整命令：
       ```
       ffmpeg -y -i bg_temp.mp4 -i role_temp.mp4
         -filter_complex "[1:v]colorkey=0x000000:0.1:0.2[role];[0:v][role]overlay=0:0"
         -c:v libx264 -pix_fmt yuv420p -crf 23 -r {fps} output.mp4
       ```
     - GIF 合成使用 `palettegen/paletteuse` 滤镜保持透明度
5. 输出到 `output/video/`，文件名：`{base_name}_composite_{timestamp}.mp4`
6. 清理临时目录（`output/temp/`）

#### 批量导出（`_batch_export_with_dialog`）

1. 从 `_show_context_menu` 接收 entries（3 元组：`skel, atlas, png_path`）
2. 按是否为合成图分类：`composite_pngs` 和 `regular_entries`
3. **只弹一次** `ExportSettingsDialog` 获取参数
4. 确认对话框显示分类统计（`普通: N，合成图: M`）
5. **合成图**：通过 `CompositeExportWorker` 后台线程串行处理（不阻塞 UI）
   - 信号：`progress(int, int, str)` / `one_finished(str, bool)` / `all_finished(int, int)`
   - 合成图导出完成后自动启动普通文件导出
6. **普通文件**：通过 `BatchExportWorker` 后台线程批量处理
   - 两者结果在 `_on_regular_all_finished` 中合并统计

#### ExportSettingsDialog 参数

| 参数 | 选项 | 默认值 |
|------|------|--------|
| 输出格式 | MP4 / GIF | 取决于调用来源 |
| 动画名称 | 手动输入 | idle |
| 时长 | 1-10 秒 | 2 |
| 帧率 | 5-60 fps | 15 |
| 缩放 | 1-8x | 2 |
| 预乘 Alpha | 勾选框 | ✅ 勾选 |
| 导出后自动打开 | 勾选框 | ❌ 不勾选 |

## 音频管理器流程

### 总体流程

导入 AS 勾选音频并完成分类导出后，自动执行以下流程（全部在 `AudioDecryptWorker` 后台线程中执行，不阻塞 UI）。点击【音频】按钮只加载已有最终产物，不会现场解密：

```
导入 AS 完成且勾选音频
       │
       ▼
复用导入进度弹窗，启动 AudioDecryptWorker
       │
       ▼
【步骤 1：转换 .bytes → .bank】
       │
       ▼
  ├── 扫描本次导出的 `data/material/assets/fmodassets/`
  ├── 筛选规则（两者需同时满足）：
  │   ├── 文件所在路径包含 fmodassets/ 子目录
  │   └── 语音（btl/system，纯数字名如 012.bytes）或 bgm（位于 bgm/ 子目录下）
  ├── 当前后处理只接收纯数字 bank 和 bgm 路径；S 前缀语音、命名 SFX、trigger/master 等素材保留在 staging 但不进入本轮 debank
  ├── 将符合条件的 .bytes 文件临时重命名为 .bank
  └── 记录日志：扫描到音频 .bytes 文件: X 个（跳过 Y 个非音频文件）
       │
       ▼
【步骤 2：解密 .bank 文件】
  ├── 增量检查：读取 `output/audio/.bank_state.json`，按 bank 来源指纹、分类目录和最终文件清单校验
  │     ├── 来源未变化、分类未变化且所有最终文件完整：跳过该 bank 的解密
  │     └── 首次处理、来源变化、分类变化或成品缺失：重新解密并更新 bank 状态
  ├── 从 `output/lua/<最新版本>/` 构建 bgm → 专辑名映射，不依赖 material Lua
  ├── `BaseSound.lua` 保存完整 bank 路径和文件名别名，`BaseSoundChapter.lua` 决定专辑归属
  ├── 调用 epic7_debank.py run(material_dir, output_dir, subdir_fn=_audio_subdir, cancel_check=...)
  ├── 脚本内部流程：
  │     ├── 递归扫描输入目录，收集所有 .bank 文件
  │     ├── 为每个 bank 创建独立的 `output/audio/.debank-temp/<job>/extract` 与 `result` 目录
  │     ├── 默认以 6 个 worker 并行；分类清理使用一次性文件索引；每个 bank 先由 vgmstream 直接读取，避免正常 bank 进入 QuickBMS
  │     ├── 解包期间轮询取消状态，取消时终止 QuickBMS 及其子进程树，不复制当前临时结果
  │     ├── quickbms 通过 -S 回调 _epic7_defsb.py，显式写入当前 job 的结果目录
  │     ├── 主线程按完成顺序执行分类回调与最终复制，避免 output/audio 并发写入
  │     │   └── 去重：目标文件存在且大小一致时跳过
  │     ├── 直解失败的 bank 才进入 QuickBMS；QuickBMS 回调再优先用 vgmstream 读取 FSB，失败后回退 fsb_aud_extr.exe，并写入提取状态文件
  │     ├── 对无音频产出的 bank 记录“空产出”，对 QuickBMS/复制异常记录“失败”
  │     └── 处理结束后清理全部 `output/audio/.debank-temp/` 临时目录，并原子更新 bank 状态
  └── 记录日志：解密完成，提取 Y 个音频文件；BGM 的同名旧分类输出会被移除，语音只在同一角色/语言作用域内清理
       │
       ▼
清理 `data/material/assets/fmodassets/`、debank `input/` 与 `output/audio/.debank-temp/` 临时目录

**输出分类说明**（`_audio_subdir`）：解密后的音频按两类分目录，不再平铺或按原目录结构：
- 语音 → `output/audio/voice/<角色ID>/<cn|jp>/`（`voice_jp`→jp，`voice_cn`→cn；角色 ID 即语音 bank 的数字名，如 001、078、121）。中日 bank 的事件文件名可能完全相同，清理旧输出时必须保留语言作用域，不能按文件名扫描整个音频目录。
- bgm → `output/audio/album/<专辑名>/`（专辑名来自 BaseSoundChapter；未匹配专辑的 bgm 归 `album/未分类/`）

未读标记从音频叶节点向上汇总：文件有“新”时，对应语言、角色/专辑、`voice`/`album` 根节点都会显示“新”；全部标为已读或播放该文件后，相关父节点同步清除。
       │
       ▼
 finished_decrypt/取消/错误信号 → 强制调用 _load_audio_list(force_reload=True)；普通页面切换复用已加载树
       │
       ▼
【步骤 3：加载音频列表】
  ├── 扫描 output/audio/ 目录中的 .wav/.ogg/.mp3
  ├── 填充表格（文件名、目录、时长、格式、大小、状态）
  ├── 新增或内容变化的文件显示红色“新”，顶部“音频”标签同步显示红点
  └── 状态栏显示：共 X 个音频文件
```

**信号**：`progress(str)` / `finished_decrypt()` / `cancelled_decrypt()` / `error(str)`
**取消机制**：用户点击处理弹窗的“取消”后，取消状态从 `AudioDecryptWorker` 传入 debank；当前 bank 及其子进程终止，已经发布到 `output/audio/` 的文件保留，队列不再续跑。替换旧任务前，主窗口等待旧 worker 真正退出，未退出时不启动新任务。

### epic7_debank.py 脚本说明

- **位置**：`tools/epic7_debank_v1_0/epic7_debank.py`
- **用法**：`python epic7_debank.py -i <input_dir> -o <output_dir> [-w 6] [--timeout 180]`
- **依赖工具**（位于 `_subcontractors/` 目录）：
  - `quickbms.exe` - Bank 文件解包工具
  - `bank-files.bms` - quickbms 脚本
  - `fsb_aud_extr.exe` - FSB 音频提取工具
  - `_epic7_defsb.py` - quickbms 回调脚本
- **特性**：
  - 支持 `-i`/`-o` 命令行参数指定输入/输出目录
  - 递归扫描子目录中的 `.bank` 文件
  - 每个 bank 文件独立临时子目录，避免同名中日 bank 互相污染
  - 默认 6 路受控并行，可通过 `-w` 或 `XL_AUDIO_DEBANK_WORKERS` 调整（上限 8）；同盘成品优先原子移动，跨盘自动回退复制；旧分类清理使用一次性文件索引
  - 使用 `output/audio/.bank_state.json` 做 bank 级增量缓存；缓存同时校验来源指纹、分类目录和最终文件清单
  - 缓存命中时跳过 QuickBMS/FSB 解码；`force=True` 导出会绕过缓存
  - 取消时轮询并终止 QuickBMS 进程树，避免取消后旧任务继续占用资源
  - 输出 bank 级统计：成功、空产出、失败、复制失败；空产出不再静默计入成功
  - 单 bank 默认 180 秒超时；FSB 子提取器默认 15 秒超时，可通过 `--timeout`、`XL_AUDIO_DEBANK_TIMEOUT` 或 `XL_AUDIO_FSB_TIMEOUT` 调整
  - bank/FSB 均优先使用 `tools/vgmstream/vgmstream-cli.exe`；直解失败才回退 QuickBMS 与 `fsb_aud_extr.exe`，两级都无音频才记为“空产出”
  - 语音文件名按来源角色作用域清理错位残留；统一外部数字前缀错位时归一化到 bank ID，混合前缀则保留并记录
  - **自定义输出子目录**：`run()` 新增 `subdir_fn(rel_path, bank_stem)` 参数，调用方自定义输出子目录（默认回退保留原目录结构），同名文件互不覆盖
  - **子目录级别去重**：目标文件存在且大小一致时跳过，避免重复处理
  - 处理完成后自动清理临时目录

- 单文件最大 10 MB（`maxBytes=10*1024*1024`）

- 文件日志级别 DEBUG，控制台日志级别 INFO
- 编码 `utf-8`

## 调试模式

调试模式用于开发测试，通过 `debug.bat` 或 `python main.py --debug` 启动。启动前先完成运行模式和日志配置：普通模式输出 INFO 摘要，Debug 模式输出 DEBUG 级别、任务上下文和外部工具诊断，并在 `logs/<session_id>/` 生成 `environment.txt`。启动后工具栏下方会多出一排「调试模式」工具栏，提供两类功能：

### 选择性导出

> **v1.29.0 起**：导入AS 的导出范围已由侧边栏「导出配置」4 类勾选（lua / 角色立绘 / FGUI图集 / 音频）接管，正式模式与调试模式通用。下方调试模式旧「导出范围」下拉框已不再生效（`_get_export_filter` 不再被调用，仅保留 `export_types` 参数兼容），后续可考虑移除。

旧「导出范围」下拉框（调试模式）曾用于选择「导入AS」要导出的资源类型：

| 选项 | 导出类型 |
|------|---------|
| 全量导出 | 所有资源类型（默认） |
| 只导出 Lua | 仅 `TextAsset`（测试 Lua 反编译用） |
| 只导出贴图 | 仅 `Texture2D`（测试贴图导出用） |
