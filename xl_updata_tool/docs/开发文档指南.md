# XL Update Tool 开发指南

本文是当前开发操作手册。架构边界见[架构与协作基线](架构与协作基线.md)，模块改动归属见[代码所有权与边界](代码所有权与边界.md)。代码结构变化时更新这几处稳定契约；不要把临时 Issue 状态追加到本指南。

架构里程碑说明：P6 到 P8 已完成 Platform/Shared 稳定入口、文档职责分工与 ownership 验收；这里只作为历史脉络，不代表当前待办。

## 环境与启动

目标是 Windows 10/11 x64，CI 当前用 Python 3.12。桌面开发默认复用仓库根目录 `XL/.venv`；启动脚本也支持工具子项目 `.venv`，并优先使用它。需要新建根环境时，从仓库根目录执行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r xl_updata_tool\requirements-dev.txt
Push-Location xl_updata_tool
..\.venv\Scripts\python.exe main.py
Pop-Location
```

`run.bat` 和 `debug.bat` 优先使用工具子项目 `.venv`，不存在时回退到仓库根 `.venv`。Release 包会内置 Python/Qt、Java 与 .NET 运行时；源码开发时只有实际调用相应链路才需要相应外部运行时。完整的便携包构建前置条件及命令见[项目 README](../README.md)。

## 代码结构

```text
app/
├── bootstrap/       # 应用上下文和 Feature 装配
├── platform/        # 文件/路径/DB/下载/进程/日志/工具定位
├── shared/          # 跨 Feature 契约和通用 Qt 能力
├── features/
│   ├── versions/    # 更新检查、版本列表和下载
│   ├── importer/    # AssetStudio 导入、分类、后处理注册
│   ├── preview/     # 图片/FGUI/Spine/视频工作台
│   ├── audio/       # 音频索引、处理、播放及未读状态
│   └── characters/  # Lua 解析、角色数据和图鉴
├── shell/           # 应用壳与通用导航
└── ui/              # 现有界面与登记的兼容入口
tests/               # 回归和契约测试
tools/               # 随应用提供的外部工具及供应方材料
```

先复用对应 Feature 的 service/controller/worker；不要把业务流程写回 `MainWindow`，不要让纯逻辑依赖 PySide6。外部程序参数、路径发现和进程终止策略应通过 `app/platform/` 与 Feature adapter 收口。

## 导入与输出数据流

AssetStudio 分类导出后，Importer 根据结果类别调用后处理器：

- Lua 反编译成品按版本写入 `output/lua/<版本>/`。
- 音频后处理写入 `output/audio/`，按来源状态做增量处理；中间解包区不是最终产物。
- 图片处理在导入完成后执行：归档 `output/spine/` 资源、建立 `preview_index.json`、切割识别到的 FGUI atlas，并导出 BurstHead、LotteryBg、PassportPic 等受支持的独立素材至 `output/game_material/`。
- 图片预览页从 `output/` 索引/文件加载；不得把扫描、切割整个 AB 或首次 Spine 归档放到页面切换路径。

输出发布失败不得覆盖已有可用文件。进度要报告当前处理项、总量、失败和取消；用户可见的错误需包含路径或外部工具诊断线索。

## 日志和崩溃诊断

运行日志写入 `logs/<session_id>/`。`app.log` 是汇总主日志，只保留应用级信息、任务/阶段收尾和关键进程结果；`error.log` 汇集 WARNING 及以上记录。Debug 模式另写 `debug.log` 并采集环境摘要。每个带任务上下文的操作独立写入 `tasks/<task_id>/task.log` 和 `tasks/<task_id>/events.jsonl`，每次下载与每次 AS 导入各有自己的日志，不会与其他任务逐行混杂。会话根目录的 `events.jsonl` 只保留摘要事件。日志记录带会话、任务、父任务、组件和阶段上下文。

启动时同时安装 Python 主线程/线程/不可报告异常钩子、`faulthandler` 与 Qt 消息处理器。未处理 Python 异常和 Qt fatal 会写入 `crash_<timestamp>.log` 并刷新日志；`fatal.log` 保存解释器可捕获的原生致命异常线程栈。正常退出写入 `application.shutdown`；下次启动若发现上一应用会话有 `application.start` 却无正常退出标记，便在旧会话写入 `crash_detected.log`，并在新会话记录 `UNCLEAN_PREVIOUS_EXIT`。该兜底只能确认进程异常结束，无法单凭日志区分程序崩溃、强制结束或系统断电。操作系统直接终止进程或故障发生在日志目录不可写时，应用内日志仍可能无法落盘，应一并检查 Windows CrashDumps。

带任务上下文的外部进程保存在 `tasks/<task_id>/external/<command_id>-<tool>/`；无任务上下文的进程保存在会话根目录 `external/<command_id>-<tool>/`。目录内保存 `stdout.log`、`stderr.log` 和 `command.json`。输出被持续排空并限制单流大小，超限时保留开头/结尾并标注截断；可用的工具原生日志会复制到 `native/`，不会移动或修改工具自己的日志。AssetStudio、SpineViewerCLI 等流程还会把退出码与业务产物校验写入命令清单；退出码为 0 不等同于导出成功。

资源流水线还会为关键交接点写入逐文件事件：AssetStudio 分类输出记录源文件、目标路径、大小及发布/回滚结果；Lua 解密记录候选文件、识别/跳过原因和输出，并在扫描、批处理准备和实际反编译三个阶段持续报告进度；音频记录 `.bytes → .bank`、bank 解包/缓存命中及每个音频文件的最终写入/跳过/失败；图片处理记录每张图集切片、每个独立素材与 Spine 归档文件；Spine 单文件导出记录骨骼、图集、动画、皮肤、参数、退出码和非空输出校验。需要追踪文件级问题时，先从 `app.log` 找到任务 ID，再查看 `tasks/<task_id>/task.log` 或 `tasks/<task_id>/events.jsonl`；外部工具原始输出位于同一任务的 `external/<command_id>-<tool>/`。逐文件事件属于详细任务日志，批量导出会增加对应任务日志体积；外部进程输出仍受大小上限保护。

每个带任务上下文的操作会生成 `tasks/<task_id>/summary.json`，记录开始/结束时间、耗时、父任务、业务结果和错误码。结果可为 `success`、`partial`、`failed`、`cancelled` 或 `unknown`；未明确验证业务结果的任务必须保留为 `unknown`，不得仅凭函数正常返回记成成功。排查时先核对最新会话，再按 `app.log` 中的任务 ID 查看对应 `task.log`、`events.jsonl`、`summary.json` 和 `external/`。分享前审查令牌、Cookie、用户标识、私有资源和无关绝对路径。

`xl_updata_tool/tools/AssetStudio/log.txt` 和 `log_prev.txt` 是随工具目录带来的历史日志，不是本应用最新会话日志；它们可能含旧机器路径。

## 自动化检查

```powershell
Push-Location xl_updata_tool
..\.venv\Scripts\python.exe -m pytest
..\.venv\Scripts\python.exe -m ruff check tests app
..\.venv\Scripts\python.exe -B -c "from pathlib import Path; files=list(Path('app').rglob('*.py'))+list(Path('tests').rglob('*.py')); [compile(p.read_text(encoding='utf-8'), str(p), 'exec') for p in files]; print(f'Compiled {len(files)} files')"
Pop-Location
```

这些检查分别覆盖仓库测试、Ruff 配置所选静态规则、Python 源文件语法编译。它们不能证明 GUI 交互、真实 Bundle、AssetStudio、SpineViewerCLI、FFmpeg 或发布包行为正确。

## 针对性人工验收

根据改动至少验证受影响的真实路径，并把环境/输入/结果写在 PR 中：

1. **版本与下载**：检查更新、重复点击防护、取消/失败反馈及恢复；抽查下载 Bundle 可读取。
2. **AssetStudio 导入**：分别试完整导入及单类 Lua 导入；确认取消和失败不会覆盖旧产物。
3. **图片/Spine**：导入后观察大类/子类进度；检查 `output/spine`、`output/character`、`output/game_material`；实际用 SpineViewerCLI 验证选定皮肤与部件，确认 cardspine PNG+完整 MP4、battlespine 使用 `motion_stander` 且无视频、活动封面静态图；检查导出画面而非仅命令行参数。
4. **图集与素材**：确认 atlas 在导入后已切割，输出目录和缩略图内容一致；验证重复导入只处理新增项且不覆盖冲突素材。
5. **音频/角色**：验证新增、已读清除、筛选/树交互和导出产物；以文件实际状态对照 UI。
6. **发布包**：运行构建脚本的完整默认路径，启动构建产物并检查自检报告；跳过运行时/测试的快速构建不能作为正式发布验收。

若机器没有游戏数据、运行时、凭据或生产服务访问权限，应明确标为未验证；不可用 pytest 通过替代实际功能验收。
