# 图片预览资源工作台设计

## 目标

把当前按文件名扫描 PNG 的图片预览器升级为面向资源身份的立绘工作台：先发现角色、Spine 和皮肤，再由用户选择皮肤和导出配置，最后分别展示角色 Spine、角色导出立绘和游戏素材。

## 已确认的需求

1. 角色立绘按角色 ID 保存，并在角色目录内按皮肤保存。
2. 角色和皮肤不能依赖不规范的文件名匹配。
3. 导出后不自动拼接立绘；拼接保留为后续显式操作。
4. 导出前在图片预览界面展示已发现的角色 Spine 与皮肤，用户勾选具体皮肤后开始导出。
5. 导出参数必须由 UI 控件选择，不要求用户输入命令行参数。
6. 角色 Spine 不需要缩略图预览，采用类似音频界面的树和勾选交互。
7. 游戏素材包含 `burst-head` 和切割后的图集；每个资源组使用独立文件夹。
8. 预览界面分为“角色 Spine”“角色导出立绘”“游戏素材”三个分页。
9. Spine、皮肤、图集和大头照都需要显示“新”状态，并且父目录状态由子项递归汇总。
10. 导出、刷新和加载过程必须异步、可取消或防重复启动，并显示实时进度和当前状态。

## 资源身份与匹配

### 角色身份

角色 ID 的解析优先级为：

1. 资源路径、Prefab 或 Asset Map 中的明确角色 ID；
2. 角色数据仓库中的已知 ID；
3. 仅当存在唯一、可验证的 5 位 ID 时才使用 Spine 文件名中的 ID。

无法可靠确认的资源放入“未匹配资源”节点，并记录原因；禁止猜测归类。

### 皮肤身份

SpineViewerCLI 的 `query <skel> --skin` 输出是皮肤发现的权威来源。每个皮肤记录至少包含：角色 ID、源 `.skel` 路径、`.atlas` 路径、Spine 内部皮肤名、附件集合指纹和展示名。

皮肤唯一键由资源身份和附件集合指纹组成。内部皮肤名用于 CLI 导出和默认显示；文件名只用于来源展示、兼容旧输出和人工确认提示，不能作为皮肤主键。

当前 `extract_motion_names()` 将 `motion_*` 字符串作为皮肤名的做法必须移除或降级为旧兼容函数，不能继续参与新导出计划。

### `burst-head` 与图集

当前仓库和现有 bundle 索引没有可靠的 `burst-head` 字面引用，因此实现资源发现时同时识别 `burst-head`、`burst_head`、`bursthead` 等命名变体，并以 AssetStudio 的资源路径、Container、Prefab 和资源类型进行确认。实际名称不确定时，UI 显示真实来源名和“Burst Head/大头照”类型，不硬编码不存在的资源。

FGUI 图集继续使用现有 `UIPackageTool` 切割流程。每个 `*_fui.bank`/`*_fui.bytes` 对应一个图集资源组，输出到 `output/fgui/<包名>/`，在新 UI 中归入“游戏素材/图集”。`burst-head` 输出到 `output/game_material/burst-head/`。

## 输出布局与兼容性

```text
output/
├── character/
│   └── <character_id>/
│       └── <skin_key>/
│           ├── <animation>.png
│           └── metadata.json
├── fgui/
│   └── <atlas_package>/
│       └── <atlas_sprite>.png
├── game_material/
│   └── burst-head/
│       └── <resource_name>.png
└── preview_state.json
```

既有 `output/character/<character_id>/*.png` 作为 legacy 未归类资源继续可读，不在首次升级时删除；重新导出后写入皮肤子目录。既有 `output/fgui/<包名>/` 路径保持不变。

## 页面与数据流

`PreviewService` 提供 Qt 无关的资源目录模型、皮肤索引、游戏素材索引、导出计划和新状态存储。`PreviewController` 负责生命周期、信号和任务状态。`PreviewPage` 只构造控件并发布语义信号。

页面分页如下：

- **角色 Spine**：树节点为角色 → 皮肤 → Spine 文件；显示“新”、缺少 atlas、未匹配等状态；勾选皮肤后打开导出配置。
- **角色导出立绘**：递归加载 `output/character/<角色>/<皮肤>/` 缩略图；支持角色/皮肤筛选、多选、分页、底部总数和已选数。
- **游戏素材**：展示 `burst-head` 和每个图集包的缩略图文件夹；图集切割结果可以打开、复制和定位。

导出流程为：发现资源 → 用户勾选皮肤 → 选择配置 → 创建导出计划 → 后台执行 → 生成皮肤图片和元数据 → 刷新预览。导出阶段不自动执行背景合成或最终立绘拼接。

## 导出配置

配置窗口使用组合框、复选框和数值微调框提供：动画、缩放比例、最大分辨率、边距、背景透明度、预乘 Alpha、输出格式和帧率。默认值来自当前 `SpineViewerCLI` 兼容参数；配置对象由纯 Python 数据类表示，CLI 命令由适配器统一构造并可独立测试。

## 新状态

资源指纹由角色 ID、源文件相对路径、文件大小、修改时间、皮肤名和附件集合指纹组成。`preview_state.json` 记录已发现指纹和已读指纹。新资源或内容变化显示“新”；勾选 Spine/皮肤资源或选择输出条目后立即标记已读，页面和父节点同步刷新，重启后状态保持。

## 错误与取消

- CLI 查询失败时保留资源节点，显示“皮肤信息读取失败”和 stderr 摘要。
- 缺少 atlas 的资源不可勾选导出，并显示具体路径。
- 导出任务禁止重复启动；导出按钮显示进度和当前文件名，点击可取消。
- 取消只停止当前任务，不清理其他分类的既有输出。
- 单个皮肤失败不会吞掉其他皮肤结果，完成摘要区分成功、跳过、失败和取消。

## 测试策略

先为资源身份、皮肤查询解析、导出计划、路径布局、状态传播和取消语义写失败测试，再实现最小代码。Qt 测试只验证页面信号、分页、树节点、禁用状态和状态刷新；CLI 使用可注入的进程运行器，避免测试依赖真实游戏资源。
