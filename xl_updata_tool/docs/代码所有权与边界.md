# XL 代码所有权与边界

本文定义 XL 在架构迁移期间的功能域 ownership 和公共文件规则。它描述当前有效边界，不要求一次性移动现有目录。

## 功能域认领范围

| 功能域 | 目标目录 | 当前迁移入口 | 普通功能改动的边界 |
|---|---|---|---|
| 音频 | `app/features/audio/` | `page.py`、`controller.py`、`service.py`、`tree.py`、`worker.py`；兼容入口为 `app/core/audio_*`、`app/core/album_map.py`、`app/ui/workers/audio_decrypt.py` | 音频页面、分类、审计、debank、播放器；不直接改 Shell |
| 角色 | `app/features/characters/` | `page.py`、`controller.py`、`service.py`；兼容入口为 `app/core/character_*`、`app/ui/views/character_view.py` | Lua 解析、角色仓库、Wiki 页面、未读和 CSV；不直接改音频或版本 |
| 预览 | `app/features/preview/` | `app/core/preview_catalog.py`、`app/ui/features/fgui_atlas.py`、Spine 适配器 | 图片、FGUI、Spine、视频导出 |
| 版本 | `app/features/versions/` | `app/core/version_*`、`app/ui/workers/download.py` | 版本列表、检查更新、下载和 Bundle 状态 |
| 导入 | `app/features/importer/` | `app/ui/workers/import_as.py`、`app/core/bundle_parser.py` | Bundle、AssetStudio、导出计划和发布事务 |
| 平台与诊断 | `app/platform/` | `app/core/path_utils.py`、`logger.py`、`database.py` 等 | 路径、文件、数据库、进程、网络、日志和诊断 |
| 共享 UI | `app/shared/qt/` | `app/ui/theme.py`、`widgets/view_chrome.py` | 主题令牌、页头、命令栏、空状态和通用控件 |
| Shell 与装配 | `app/shell/`、`app/bootstrap/` | `app/ui/main_window.py`、`main.py` | 导航、任务宿主、Feature 注册和运行时装配 |

## 当前有效规则

1. 新功能优先进入对应功能域，不继续向 `main_window.py` 添加领域状态和业务流程。
2. Shell 不得直接导入角色解析器、音频仓库、数据库、AssetStudio、debank 或其他 Feature 内部实现。
3. 新 Page 自己拥有控件，只暴露语义信号和展示状态方法，不调用 `parent._xxx`，不返回 `controls_dict`。
4. 应用服务和领域逻辑不得依赖 PySide6；Qt Worker 只负责线程生命周期、取消、进度和结果信号。
5. Feature 之间通过契约、结果对象和显式后处理器通信，不互相导入内部实现。
6. `app/core` 和旧 `app/ui` 在迁移期作为兼容层，不接受与迁移无关的新业务堆叠。
7. `shell`、`bootstrap`、`platform`、`shared` 是公共架构区，改动需要单独 Issue、影响说明和额外审查。
8. 输出目录、数据库、日志目录、Qt 信号和取消语义属于稳定契约，结构迁移不得顺手修改。
9. Audio P1a 期间允许 MainWindow 保留旧业务方法和控件别名作为适配层；新音频 UI 代码必须进入 `app/features/audio/page.py`，目录服务不得依赖 Qt。
10. Audio P1 完成后，音频页面信号、播放器、选择状态和解密任务统一由 `app/features/audio/controller.py` 管理；MainWindow 只接收任务结果并参与导入总流程。
11. Characters P2 完成后，角色页面信号、角色索引、Lua 解析协调、未读状态和 CSV 入口统一由 `app/features/characters/` 管理；MainWindow 只参与导航和导入结果接入。

## 提交边界

- 音频、角色、预览、版本等普通功能 PR 应集中在单一 Feature 目录和对应测试。
- 修改 Shell 或跨 Feature 契约时，必须说明为什么不能在 Feature 内完成，并补充架构测试。
- 迁移期允许兼容导出和双入口；确认调用方和测试全部切换后，才删除旧模块。
- 每个阶段使用本地小提交；最终 PR 前统一完成测试、静态检查、文档同步和差异审查。

## 当前迁移顺序

`P0 架构契约` → `Audio` → `Characters` → `Versions` → `Importer` → `Preview` → `Platform/Shared 收缩` → `文档降冲突` → `ownership 验收`。
