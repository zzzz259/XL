# XL Update Tool 版本历史

> 本文件只记录项目版本变更；使用方法请阅读 [项目 README](../README.md)，实现细节请阅读 [开发文档指南](开发文档指南.md)。

## 版本历史

### v1.53.0 (2026-08-24)

#### 架构迁移 P0：建立 Feature ownership 与依赖门禁（Issue #39）

- 新增无 Qt 的 Feature/Page/Controller/Service/Worker/ImportResult 共享契约，作为后续功能域迁移的稳定边界。
- 新增 `app/bootstrap/context.py` 和 `app/bootstrap/app_factory.py`，提供显式运行时上下文和 Feature 装配骨架；当前不接管旧 MainWindow，保持运行行为不变。
- 新增代码所有权与边界文档，明确音频、角色、预览、版本、导入、平台、共享 UI 和 Shell 的修改范围。
- 新增架构回归测试，约束新组合根/共享契约不依赖 Qt，并验证 Feature 注册顺序、重复 key 和导入结果契约。
- 本轮不移动 `app/core`、`app/ui`，不改变导出结果、数据目录、日志结构、Qt 信号或取消语义。

### v1.52.0 (2026-08-23)

#### 日志可观测性与 Normal/Debug 启动模式收口（Issue #38）

- 启动入口先解析 `--debug`，再配置日志和导入主窗口；普通模式与 Debug 模式拥有不同的日志级别和外部进程诊断策略。
- 日志按启动会话写入 `logs/<session_id>/`，包含 `app.log`、`error.log`；Debug 额外生成 `debug.log` 和 `environment.txt`。
- 为导入、Lua、音频 Worker 增加 task ID、组件和阶段上下文；日志记录任务开始/完成、阶段耗时和关键外部工具退出信息。
- 新增 AssetStudio/Spine CLI 外部进程诊断包装，失败时记录退出码、耗时和 stdout/stderr 尾部；新增顶层/线程异常报告。
- 本轮不改 UI 布局、正式数据目录隔离、失败 staging 保留和资源导出业务契约。

### v1.51.0 (2026-08-23)

#### 音频完整性审计与文件树交互（Issue #35）

- 处理完成后对照最新 Lua 的 `BaseSound.lua`、`BaseSoundChapter.lua` 和 bank 增量状态，记录已配置 BGM 缺口及配置表之外的未分类 BGM。
- 音频树支持目录递归勾选；普通点击保持单选，按住 Ctrl 可追加或取消多个文件/目录选择，目录节点显示全选或半选状态。
- “新”状态按所有叶节点聚合到同级目录和最外层目录，统一使用红色状态文字；播放时按完整相对路径清除对应未读记录。
- 音频页首次进入或处理完成时加载列表，普通页面切换复用已有树；刷新按钮显式重建列表。播放进度条在拖动期间保持用户位置，释放后提交 seek。

### v1.50.0 (2026-08-23)

#### 音频 debank 直解提速（Issue #35）

- `.bank` 先由内置 vgmstream 直接解码，正常语音与 BGM 不再经过 QuickBMS 和旧 FSB 提取器；直解失败的 bank 保留 QuickBMS/FSB 兼容回退。
- vgmstream 使用多子流全量输出和忽略循环信息，发布前归一化子流序号，保持现有 WAV 文件名契约。
- debank 默认并行度调整为 6，可通过 `-w` 或 `XL_AUDIO_DEBANK_WORKERS` 覆盖；分类清理改为一次性文件索引；同盘临时成品优先原子移动，跨盘自动回退复制。
- 基于本地完整 AB 版本实测：同批 12 个 bank 从 29.539 秒降至 4.031 秒；735 个 bank 的完整集成链路耗时 458.463 秒，712 个直接成功、23 个回退后空产出，复制失败为 0。
- 新增直解、命名归一化、旧链路回退和同盘移动测试；保留现有增量缓存、取消控制、BGM 分类和 WAV 输出格式。

### v1.49.0 (2026-08-23)

#### 音频 BGM、取消控制与增量缓存收口（Issue #35）

- 修复 BGM 复制前清理逻辑误删当前 `.debank-temp` 临时源文件的问题；专辑音频可正常进入 `output/audio/album/`，旧专辑分类清理仍保留。
- “全部标为已读”现在明确写回 Qt 树节点数据，叶节点、语言/角色/专辑节点和最外层分类的“新”文字与颜色同步清除。
- 音频取消贯穿 worker、bank 解包和 QuickBMS 子进程；取消会终止当前进程树，保留已发布文件，不会自动启动下一轮任务。
- `output/audio/.bank_state.json` 记录 bank 来源指纹、分类目录和最终文件清单；来源未变化、分类未变化且成品完整时跳过重复解密，缺文件或分类变化会自动重新处理。
- 保持 WAV 等现有输出格式和 vgmstream 回退路径不变；新增取消、BGM staging、未读清除和缓存失效回归测试。

### v1.48.1 (2026-08-21)

### v1.48.0 (2026-08-21)

#### FSB 解码回退与语音前缀收口（Issue #35）

- 新增项目内 vgmstream Windows CLI 运行时；`fsb_aud_extr.exe` 超时、异常退出或空产出时自动回退，已用真实 E20 FSB 验证可输出 WAV。
- FSB 回调写入 `.extract_status.json`，主 debank 流程读取该状态，避免 QuickBMS 仍返回 0 时把底层提取失败误判为成功。
- 语音 bank 若全部文件使用统一的异号数字前缀，则按外层 bank ID 归一化；混合前缀不强行改名，避免误伤共享音频。
- 新增 FSB 回退、失败状态传播和语音前缀归一化测试；保留原提取器正常成功路径。

### v1.47.0 (2026-08-21)

#### 音频 bank 缺口诊断、同名隔离与受控并行（Issue #35）

- 每个 bank 使用独立的 `_tempo/<job>/extract` 与 `result` 目录，QuickBMS/FSB 不再复用按角色编号命名的共享临时目录，修复中日同名 bank 的结果覆盖风险，并清理历史错位残留。
- 运行时临时根目录改为可写的 `output/audio/.debank-temp/`，处理结束自动清理，不再要求工具目录具备写权限。
- debank 默认以 2 个 worker 并行处理，最终复制和分类回调保持串行；支持 `-w` 与 `XL_AUDIO_DEBANK_WORKERS` 调整并行度。
- 新增 bank 级成功、空产出、QuickBMS 失败和复制失败统计；活动音乐缺口不再被最终“失败 0”掩盖，便于直接定位 E20 一类问题。
- 语音输出清理限制到当前角色与语言目录，重新导出时会移除旧的跨角色错位文件；提取器生成的连续重复 `battle_hit_01_1..N` 文件归一化为标准编号，修复 080 命名不一致。实测 JP 064/095 bank 内部仍存在前缀互换，已记录为源资源命名异常，未强行改名。
- `_epic7_defsb.py` 显式接收 job 结果目录并检查 `fsb_aud_extr.exe` 返回码；新增并行隔离、空产出、错位清理和文件名归一化测试。
- 新增 bank 级超时保护，默认单 bank 最多处理 180 秒，可用 `--timeout` 或 `XL_AUDIO_DEBANK_TIMEOUT` 调整；E20 等底层提取器卡住时只记为失败，不阻塞整批导出。

### v1.46.0 (2026-08-21)

#### 音频导出、分类与精准解密流程收口（Issue #35）

- 仅勾选音频时读取 `assets_map.json`，按 `assets/fmodassets` 反查并隔离命中的 AB 包；映射不可用时保留兼容回退并记录日志。
- 导入 AS 成功后自动执行音频后处理，复用导入进度弹窗；音频处理结束前不关闭弹窗或恢复导入按钮。
- 音频 bank/bytes 只作为临时中间态，处理完成后清理 `data/material/assets/fmodassets/` 和 debank 输入目录；最终音频只保留在 `output/audio/`。
- 音频按 output 现有内容增量写入，不做 Lua 式版本隔离；新增/变化音频维护独立未读状态，顶部“音频”标签和列表状态显示红色“新”。
- 专辑映射改为读取最新已留存的 `output/lua/<版本>/`，使用 BaseSound 完整 bank 路径别名和 BaseSoundChapter 章节关系；修正活动 BGM 33、34 归入第五专辑。
- 音频管理器移除“开始解密”，页面切换只加载最终产物；列表改为整行单选、互斥勾选和无蓝色选中高亮，新增“全部标为已读”。
- 新增音频仓库、专辑映射、音频 AB 筛选和临时清理测试；不改 Lua 版本隔离、FGUI 和 Spine 流程。

#### 音频中日语音同名覆盖修复

- 修正音频后处理的旧分类清理范围：`voice_cn` 与 `voice_jp` 分别限定在对应的 `voice/<角色ID>/cn`、`voice/<角色ID>/jp` 作用域内，不再因 bank/事件文件同名而删除另一语言。
- BGM 仍保留跨旧专辑目录清理能力；新增中日同名语音回归测试，防止语言隔离再次回退。
- 音频树的未读“新”标记由叶节点向上汇总到语言、角色/专辑和最外层分类文件夹。

- 启动回归修复：顶部导航图标名称统一先转换为 QIcon，再交给 Qt 按钮；新增工具栏构建 smoke，避免 PySide6 的 setIcon 类型错误阻断启动。

## 附录 B：性能排查清单

当程序出现卡顿或性能问题时，按以下清单逐项确认信息，以便定位瓶颈。

### B.1 需确认的信息

| 编号 | 确认项 | 说明 | 排查方法 |
|------|--------|------|----------|
| 1 | `data/bundles/` 目录下版本文件夹数量 | 文件夹数量过多会导致版本列表加载变慢 | 资源管理器中查看 `data/bundles/` 下的子目录数量 |
| 2 | `output/character/` 目录中图片数量 | 图片数量过多会导致预览视图加载卡顿（缩略图生成、网格渲染） | 资源管理器中查看 `output/character/` 下的 `.png` 文件数量 |
| 3 | 卡顿发生时机 | 首次点击 = 可能是导出耗时；每次点击 = 可能是渲染或内存问题 | 分别记录首次点击和后续点击的响应时间 |
| 4 | 日志文件大小 | 日志过大可能影响写入性能 | 查看 `logs/app.log` 文件大小；当前日志系统已使用 `RotatingFileHandler` 限制单文件 10MB，`backupCount=0` 超出时自动清空重写 |
| 5 | 电脑配置 | CPU 核心数、内存容量、硬盘类型（SSD/HDD）直接影响 I/O 密集型操作 | 任务管理器 → 性能 标签页查看 |
| 6 | 进程资源占用 | 卡顿时 Python 进程的 CPU/内存占用情况可帮助判断瓶颈类型 | 任务管理器 → 详细信息 → 找到 `python.exe`，查看 CPU 和内存列 |

### B.2 性能瓶颈分析指引

> **v1.20.0 已实施优化**：以下耗时操作均已移至 QThread 后台线程，UI 不会阻塞：
> - 图片预览导出 → `PreviewExportWorker`
> - 音频解密 → `AudioDecryptWorker`
> - 批量合成图视频导出 → `CompositeExportWorker`
> - 批量普通文件导出 → `BatchExportWorker`
> - `_as_temp` 复制 + 修复 → `_FixWorker`
>
> 若卡顿仍然出现，应优先检查是否在 UI 线程中执行了新的同步操作。

根据上述信息，可初步判断瓶颈类型：

| 症状 | 可能原因 | 优化方向 |
|------|----------|----------|
| 首次点击卡顿，后续正常 | SpineViewerCLI 导出耗时（I/O 密集） | 检查 `.skel` 文件数量和大小；确认硬盘为 SSD |
| 每次点击都卡顿 | 缩略图渲染或内存不足 | 检查 `output/character/` 图片数量；考虑分页加载 |
| CPU 占用 100% | SpineViewerCLI 或 FFmpeg 子进程满载 | 属正常现象，等待子进程完成即可 |
| 内存占用持续增长 | 图片缓存未释放或 `QPixmap` 泄漏 | 检查 `DragListWidget` 的 `QListWidgetItem` 是否正确回收 |
| 硬盘 I/O 等待高 | 大量小文件读写（如 .bank 解密、PNG 导出） | 确认硬盘类型；HDD 下小文件 I/O 性能较差 |

### B.3 日志系统现状

当前日志系统（`app/core/logger.py`，v1.20.0 已优化）配置：

- **日志分割方式**：按大小分割（`RotatingFileHandler`），固定文件名 `logs/app.log`
- **maxBytes 限制**：✅ 10 MB（`maxBytes=10*1024*1024`）
- **backupCount 限制**：✅ 0（仅保留当前文件，超出大小时自动清空重写）
- **编码**：`utf-8`（支持中文字符）
- **日志级别**：DEBUG（文件）/ INFO（控制台）
- **配置代码**：
  ```python
  from logging.handlers import RotatingFileHandler
  file_handler = RotatingFileHandler(
      log_file,
      maxBytes=10 * 1024 * 1024,
      backupCount=0,
      encoding="utf-8"
  )
  ```
