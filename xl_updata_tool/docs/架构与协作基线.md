# XL Update Tool：架构与运行目录契约

本文描述当前实现中可依赖的模块边界和数据流。模块清单不是重构路线图；具体目录以代码为准，版本变更见[版本历史](版本历史.md)。

## 主流程

```text
版本检查 → 生成下载计划 → 下载并校验 Bundle → AssetStudio 分类导入
    → 发布 Lua / 音频 / 图片预处理 → 图片、角色、音频页面消费产物
```

AssetStudio 导入完成后，已注册的后处理器运行各自的发布流程。图片预处理会发现并归档 Spine 输入、切割 FGUI 图集、导出受支持的独立素材并生成索引；进入图片预览页不会再做首次重型处理。

## 模块职责

| 模块 | 职责 |
|---|---|
| `app/bootstrap/` | 创建应用上下文、注册并组装各 Feature |
| `app/platform/` | 路径、文件、数据库、下载、子进程、日志/诊断及外部工具定位 |
| `app/shared/` | 跨 Feature 稳定契约和共享 UI 基础 |
| `app/features/versions/` | 版本列表、更新检查、下载、Bundle 状态 |
| `app/features/importer/` | AssetStudio 导入、分类和后处理调度 |
| `app/features/preview/` | 图片/游戏素材、FGUI、Spine、视频预览及导出 |
| `app/features/audio/` | 音频扫描、增量处理、播放器、分类和未读状态 |
| `app/features/characters/` | Lua 角色数据解析、数据仓库、角色图鉴和 CSV |
| `app/shell/`、`app/ui/` | 应用 Shell、页面装配和明确登记的兼容入口 |
| `tests/` | 桌面工具回归、契约和纯逻辑测试 |

平台、领域服务和导入/导出策略不依赖 UI。耗时工作在 Worker/服务边界执行；Shell 负责页面导航、通用任务状态和生命周期，不直接持有 Feature 的领域规则。`app/core/` 不属于当前生产架构；`app/ui/` 中的旧入口只有明确兼容用途，不在其中新增领域逻辑。

## 运行数据与最终产物

所有根目录通过 `app/platform/paths.py` 解析；冻结版可执行文件以 EXE 所在目录作为持久化根目录。

| 路径 | 当前用途 |
|---|---|
| `data/bundles/<版本>/` | 下载的原始 Bundle 与资源映射 |
| `data/material/` | AssetStudio 导出及可重建的中间素材 |
| `data/seeds/`、`data/xl_updata.db` | 版本分类种子及版本/Bundle 元数据 |
| `output/lua/<版本>/` | 按版本发布的 Lua 文件 |
| `output/audio/` | 去重/增量处理后的音频成品 |
| `output/spine/<资源家族>/<来源指纹>/` | 归档的 Spine 文件、图集页贴图及来源索引 |
| `output/character/<角色ID>/` | 角色立绘/战斗小人静态图和立绘视频 |
| `output/game_material/` | FGUI 切图与 BurstHead、LotteryBg、PassportPic 等素材 |
| `output/preview_index.json`、`output/preview_state.json` | Spine 预览索引与图片未读状态 |
| `output/character_data/` | 本地角色结构化数据及版本缓存 |
| `logs/<会话ID>/` | 会话日志、Debug 环境摘要和崩溃诊断 |

图片工作台读取 `output/` 成品目录；`data/material/` 是暂存区，不是最终交付目录。导入后处理失败必须在日志/进度结果中暴露，不应被页面切换掩盖。

## Spine 与图集契约

- `cardspine`、`battlespine`、`eventcovers` 是独立资源家族；按角色身份和皮肤分组，不按可能不规范的皮肤文件名做唯一身份判断。
- 同一皮肤关联的角色与背景部件作为整体一次交给 SpineViewer 调用，不在用户树中把背景作为独立皮肤。
- 内置默认配置按资源家族区分：角色立绘导出 PNG 与完整动画 MP4；战斗小人使用 `motion_stander` 皮肤、只导出 PNG；活动封面只导出 PNG。详见[开发指南](开发文档指南.md)和实现 `app/features/preview/export_presets.py`。
- 原始 `.skel`/`.atlas` 归档名会归一化 Unity/AssetStudio 传输后缀；归档按来源路径和内容指纹累计，跨版本相同角色资源不会互相覆盖。
- 图片预处理在导入后处理阶段执行。游戏图集按其资源类型切割到 `output/game_material/`，不是在打开预览页时临时裁切。

## 可靠性与数据保护

- `data/material/` 可重建；不要把 `output/`、数据库、下载 Bundle 和用户本地状态视为可随手清理的缓存。
- 替换旧成品前验证新结果；失败或取消时保留既有有效文件，并报告部分成功、失败和取消状态。
- 增量判断需要基于明确的资源身份/来源指纹；不能仅凭目录非空判定全量处理完成。
- 清理任务应限定在当前任务拥有的临时目录；不得递归删除用户指定目录以外的内容。

## 修改和验收

先定位所属 Feature，避免跨域导入内部实现。普通改动只改该 Feature 和对应测试；Shell、Platform、Shared、运行目录或后处理契约变更需在 PR 解释影响。

在 `xl_updata_tool/` 使用项目虚拟环境运行 `python -m pytest`、`python -m ruff check tests app`。这只能验证自动化覆盖的部分；SpineViewer、AssetStudio、FFmpeg 和真实资源输入需针对对应产物做实际 smoke 验证。具体验证入口见[开发文档指南](开发文档指南.md)。
