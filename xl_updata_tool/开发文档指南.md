# XL Update Tool 开发文档指南

## 项目概述

XL Update Tool 是一个基于 PySide6 的桌面应用，用于下载和浏览游戏资源包。

### 功能特性

- 版本更新检测与下载
- 资源包全量/增量下载
- 资源包浏览与管理
- 下载进度实时显示
- 日志记录与错误追踪
- 自动导出资源到 material 目录
- 批量预览图片（使用 SpineViewerCLI 导出 .skel 为 PNG）
- 皮肤（Skin）导出：从 .skel 二进制提取 `motion_*` 名称，逐个导出各表情独立图片
- 角色图片预览（多选[Ctrl/Shift] + 拖放复制 + 自适应菜单[单选/多选/合成图] + 批量导出 + 导出参数对话框 + 配对合成 + 多动画导出）
- 合成图视频导出（SpineViewerCLI 直接导出 MP4 + FFmpeg colorkey 叠加合成）
- 预乘 Alpha（--pma）选项支持
- 音频管理器（.bank 解密 + 音频播放 + 批量导出）
- 工具栏：检查更新 / 导入AS / 图片预览 / 音频 / 刷新

## 核心模块说明

### core/downloader.py

提供下载相关功能：

- `CheckUpdateThread` - 检查更新线程
- `DownloadWorker` - 下载工作线程，支持：
  - 信号：`progress`, `item_done`, `item_skip`, `item_fail`, `all_done`, `error`
  - 自动重试机制（最多3次）
  - MD5 校验

### core/database.py

SQLite 数据库管理，存储版本信息和资源包路径。

### core/logger.py

日志系统，配置：
- 固定日志文件：`logs/app.log`（使用 `RotatingFileHandler`）
- 单文件最大 10 MB（`maxBytes=10*1024*1024`），超出时自动清空重写
- 备份数量 0（`backupCount=0`），仅保留当前日志文件
- 文件日志级别 DEBUG，控制台日志级别 INFO
- 编码 `utf-8`，支持中文字符
- 同时输出到控制台和文件

### ui/main_window.py

主窗口控制器，包含：
- 版本列表展示
- 下载按钮与进度管理
- 资源包浏览入口
- 后台工作线程（QThread）：
  - `PreviewExportWorker` - 图片预览导出线程（.skel → PNG，含配对合成 + 皮肤导出）
  - `AudioDecryptWorker` - 音频解密线程（.bytes → .bank → 解密）
  - `CompositeExportWorker` - 批量合成图视频导出线程
  - `BatchExportWorker` - 批量普通文件导出线程
  - `ImageLoadWorker` - 缩略图异步加载线程

### ui/asset_browser.py

资源浏览器窗口，包含：
- `_FixWorker` - 文件修复线程（复制并修复文件头，支持大小去重）
- `_MapWorker` - AssetStudio 解析线程（生成资源映射）
- `_ExtractWorker` - 资源导出线程
- 实时进度显示（修复进度 + 加载进度）
- 资源筛选、预览、导出功能

## 资源浏览流程

> **v1.21.0 更新**：导入AS 已集成到主界面，不再弹出独立的资源浏览器窗口。
> 所有操作（修复、解析、导出分类）在主界面后台执行，进度通过下载进度条和状态栏显示。

点击"导入AS"后，执行以下流程（全部在 `ImportASWorker` 后台线程中执行，不阻塞 UI）：

1. **获取版本文件列表**：
   - 从数据库获取选中版本的所有 Bundle 本地路径
   - 如果文件列表为空，提示"此版本没有已下载的 bundle，请先下载"
2. **阶段 1：修复文件头**（`_stage_fix`）：
   - 直接对原始 `.bundle` 文件调用 `fix_bundle_inplace`（不再复制到 `_as_temp`）
   - 实时更新进度条："修复文件头: X/总数"
   - 单个文件修复失败时记录日志并跳过，不中断整体流程
   - 如果所有文件修复失败，提示"所有文件修复失败，请删除该版本并重新下载"
3. **阶段 2：解析资源**（`_stage_map`）：
   - 调用 AssetStudio CLI 生成资源映射（`--map_op Both --map_type JSON`）
   - 实时更新进度条："解析资源: X/总数"
   - 输出 `assets_map.json` 到 `data/bundles/{ts}/_map/`
4. **阶段 3：导出分类**（`_stage_export`）：
   - 清空 `data/material/` 旧目录
   - 按类型逐个调用 AssetStudio CLI 导出（`--group_assets ByContainer --export_type Convert`）
   - 实时更新进度条："导出分类: X/类型总数"
   - 清理 `.prefab` 后缀（AssetStudio CLI 可能错误添加）
   - 统计导出文件总数
5. **完成提示**：
   - 成功：弹窗"导入完成！文件已分类到 data/material/（共 N 个文件）"
   - 失败：弹窗"文件可能损坏，请点击【删除已下载】并重新下载"

### 进度显示

| 阶段 | 进度条格式 | 状态栏 |
|------|-----------|--------|
| 修复文件头 | `修复文件头: 150/2956` | `导入AS: 修复文件头 150/2956` |
| 解析资源 | `解析资源: 50/200` | `导入AS: 解析资源 50/200` |

## 图片预览与导出流程

### 图片预览流程

点击【图片预览】按钮后：

1. **切换视图**：隐藏版本列表表格，显示图片预览视图
2. **缓存检查**：检查 `output/character/` 目录是否已有 PNG 图片
   - 已有图片：直接加载（日志：`预览目录已存在 X 张图片，直接加载`，状态栏显示 `来源：缓存`）
   - 无图片：启动后台导出线程后加载（状态栏显示 `来源：刚导出`）
3. **图片导出**（`PreviewExportWorker` 后台线程）：
   - 在后台线程执行，不阻塞 UI（进度条实时反馈 `导出中... X/总数`）
   - 扫描 `data/material/` 目录中的 `.skel` 文件
   - **去重优化**：`force=False` 时，若 `output/character/{base_name}.png` 已存在且大小 > 0，则跳过该文件
   - **强制刷新**：点击【🔄 重新加载图片】时清空目录并 `force=True` 重新导出
   - 对每个 `.skel` 执行以下两步导出：
     - **动画帧导出**（`MainWindow._export_animation_frames`）：
       - 从 `.skel` 二进制文件提取动画名称（正则 `motion_[a-zA-Z0-9_]+`）
       - 遍历每个动画，使用 SpineViewerCLI 导出第一帧 PNG
       - 命令：`export -f Png --time 0 --duration 1 --fps 1 --scale 4 --max-resolution 8192 --pma`
       - 支持 `--pma` fallback：带 `--pma` 失败时自动重试不带 `--pma`
     - **皮肤图片导出**（`MainWindow._export_skel_skins`）：
       - 从 `.skel` 二进制文件提取 `motion_*` 名称作为皮肤列表
       - 遍历每个皮肤，使用 SpineViewerCLI 导出独立 PNG
       - 动画固定为 `idle`，添加 `--skins {skin_name}` 参数
       - 输出文件名：`{base_name}_{skin_name}.png`
       - 支持 `--pma` fallback
   - **配对合成**：识别 `xxx.skel + xxx_bg.skel` 配对，合成 `{xxx}_composite.png`（去重：已存在则跳过）
   - 信号：`progress(int, int)` / `export_finished(bool, str)` / `error(str)`
   - 支持取消：切换视图时调用 `cancel()` 终止后台任务
4. **缩略图显示**：网格展示，支持 Ctrl/Shift 多选、拖放复制

### 视频导出流程

#### 普通视频导出（`_export_with_dialog`）

1. 弹出 `ExportSettingsDialog` 对话框
2. 用户选择：格式（MP4/GIF）、动画、时长、帧率、缩放、预乘 Alpha
3. 从 PNG 文件名提取皮肤名（`motion_*`），如有则添加 `--skins` 参数
4. 构建 SpineViewerCLI 命令：
   ```
   SpineViewerCLI.exe export <skel> -f Mp4/Gif -o <output> -a <animation>
     --atlas <atlas> --duration <dur> --fps <fps> --scale <scale>
     [--pma] [--skins <skin_name>]
   ```
5. 输出到 `output/video/`（MP4）或 `output/character/`（GIF）

#### 合成图视频导出（`_export_composite_video`）

采用 **分别导出角色和背景 MP4 → FFmpeg 叠加合成** 的方案：

1. 从合成图文件名（如 `xxx_composite.png`）解析基础名 `xxx`
2. 在 `self._skel_map` 中查找 `xxx.skel`（角色）和 `xxx_bg.skel`（背景）
3. 弹出 `ExportSettingsDialog` 对话框获取参数
4. 调用 `_export_composite_video_with_params` 执行：
   - **步骤 1**：导出角色 MP4（`role_temp.mp4`）
     - 使用 SpineViewerCLI `export -f Mp4`，添加 `--color "#00000000"` 透明背景
     - 根据 `skin_name` 参数决定是否添加 `--skins`
   - **步骤 2**：导出背景 MP4（`bg_temp.mp4`）
     - 不应用皮肤参数
   - **步骤 3**：FFmpeg 叠加合成
     - 调用 `_ffmpeg_composite_videos` 方法
     - FFmpeg 路径通过 `_get_ffmpeg_path()` 获取（优先 `tools/SpineViewer/ffmpeg.exe`）
     - MP4 滤镜：`colorkey=0x000000:0.1:0.2`（去除角色视频黑色背景）
     - 完整命令：
       ```
       ffmpeg -y -i bg_temp.mp4 -i role_temp.mp4
         -filter_complex "[1:v]colorkey=0x000000:0.1:0.2[role];[0:v][role]overlay=0:0"
         -c:v libx264 -pix_fmt yuv420p -crf 23 -r {fps} output.mp4
       ```
     - GIF 合成使用 `palettegen/paletteuse` 滤镜保持透明度
5. 输出到 `output/video/`，文件名：`{base_name}_composite_{timestamp}.mp4`
6. 清理临时目录（`output/temp/`）

#### 批量导出（`_batch_export_with_dialog`）

1. 从 `_show_context_menu` 接收 entries（3 元组：`skel, atlas, png_path`）
2. 按是否为合成图分类：`composite_pngs` 和 `regular_entries`
3. **只弹一次** `ExportSettingsDialog` 获取参数
4. 确认对话框显示分类统计（`普通: N，合成图: M`）
5. **合成图**：通过 `CompositeExportWorker` 后台线程串行处理（不阻塞 UI）
   - 信号：`progress(int, int, str)` / `one_finished(str, bool)` / `all_finished(int, int)`
   - 合成图导出完成后自动启动普通文件导出
6. **普通文件**：通过 `BatchExportWorker` 后台线程批量处理
   - 两者结果在 `_on_regular_all_finished` 中合并统计

#### ExportSettingsDialog 参数

| 参数 | 选项 | 默认值 |
|------|------|--------|
| 输出格式 | MP4 / GIF | 取决于调用来源 |
| 动画名称 | 手动输入 | idle |
| 时长 | 1-10 秒 | 2 |
| 帧率 | 5-60 fps | 15 |
| 缩放 | 1-8x | 2 |
| 预乘 Alpha | 勾选框 | ✅ 勾选 |
| 导出后自动打开 | 勾选框 | ❌ 不勾选 |

## 音频管理器流程

### 总体流程

点击【音频】按钮后，自动执行以下流程（全部在 `AudioDecryptWorker` 后台线程中执行，不阻塞 UI）：

```
用户点击【音频】
       │
       ▼
切换到音频管理器视图（隐藏版本列表）
       │
       ▼
启动 AudioDecryptWorker 后台线程
       │
       ▼
【步骤 1：转换 .bytes → .bank】
  ├── 扫描 data/material/ 目录（递归）
  ├── 筛选规则（两者需同时满足）：
  │   ├── 文件名（不含扩展名）完全由数字组成（如 012.bytes）
  │   └── 文件所在路径包含 fmodassets/ 子目录
  ├── 不满足条件的 .bytes 文件完全忽略（不重命名、不复制、不处理）
  ├── 将符合条件的 .bytes 文件重命名为 .bank（原地重命名）
  ├── 复制到解密工具 input 目录（去重：大小一致则跳过复制）
  └── 记录日志：扫描到音频 .bytes 文件: X 个（跳过 Y 个非音频文件）
       │
       ▼
【步骤 2：解密 .bank 文件】
  ├── 去重检查：若 output/audio/ 已有音频文件，跳过解密（避免重复处理）
  ├── 调用 epic7_debank.py -i data/material -o output/audio
  ├── 脚本内部流程：
  │     ├── 递归扫描输入目录，收集所有 .bank 文件
  │     ├── 遍历每个 .bank 文件，获取其相对于输入目录的路径
  │     ├── 对每个 .bank 调用 quickbms.exe 解包
  │     ├── quickbms 通过 -S 回调 _epic7_defsb.py 提取音频
  │     ├── 将提取的音频文件复制到对应输出子目录下（保留原始目录结构）
  │     │   └── 例如：data/material/fmodassets/voice_cn/xxx.bank → output/audio/fmodassets/voice_cn/xxx.wav
  │     │   └── 去重：目标文件存在且大小一致时跳过
  │     └── 清理本次 result 目录，避免影响下一个 bank
  └── 记录日志：解密完成，提取 Y 个音频文件

**目录结构保留说明**：解密后的音频文件保留与输入目录 `data/material/` 一致的相对路径结构。例如 `fmodassets/voice_cn/` 和 `fmodassets/voice_jp/` 中的同名文件将分别输出到 `output/audio/fmodassets/voice_cn/` 和 `output/audio/fmodassets/voice_jp/`，不再相互覆盖。
       │
       ▼
finished_decrypt 信号 → 自动调用 _load_audio_list()
       │
       ▼
【步骤 3：加载音频列表】
  ├── 扫描 output/audio/ 目录中的 .wav/.ogg/.mp3
  ├── 填充表格（文件名、时长、格式、大小）
  └── 状态栏显示：共 X 个音频文件
```

**信号**：`progress(str)` / `finished_decrypt()` / `error(str)`
**取消机制**：切换视图时调用 `cancel()` 终止后台任务

### epic7_debank.py 脚本说明

- **位置**：`tools/epic7_debank_v1_0/epic7_debank.py`
- **用法**：`python epic7_debank.py -i <input_dir> -o <output_dir>`
- **依赖工具**（位于 `_subcontractors/` 目录）：
  - `quickbms.exe` - Bank 文件解包工具
  - `bank-files.bms` - quickbms 脚本
  - `fsb_aud_extr.exe` - FSB 音频提取工具
  - `_epic7_defsb.py` - quickbms 回调脚本
- **特性**：
  - 支持 `-i`/`-o` 命令行参数指定输入/输出目录
  - 递归扫描子目录中的 `.bank` 文件
  - 每个 bank 文件独立临时子目录，避免冲突
  - **保留目录结构**：输出目录保持与输入目录一致的相对路径，同名文件互不覆盖
  - **子目录级别去重**：目标文件存在且大小一致时跳过，避免重复处理
  - 处理完成后自动清理临时目录

## 导出资源目录结构

资源导出功能将 Unity 资源提取到 `data/extracted/` 目录下，目录结构如下：

```
data/extracted/
├── assets/
│   ├── art/

## 附录 B：性能排查清单

当程序出现卡顿或性能问题时，按以下清单逐项确认信息，以便定位瓶颈。

### B.1 需确认的信息

| 编号 | 确认项 | 说明 | 排查方法 |
|------|--------|------|----------|
| 1 | `data/bundles/` 目录下版本文件夹数量 | 文件夹数量过多会导致版本列表加载变慢 | 资源管理器中查看 `data/bundles/` 下的子目录数量 |
| 2 | `output/character/` 目录中图片数量 | 图片数量过多会导致预览视图加载卡顿（缩略图生成、网格渲染） | 资源管理器中查看 `output/character/` 下的 `.png` 文件数量 |
| 3 | 卡顿发生时机 | 首次点击 = 可能是导出耗时；每次点击 = 可能是渲染或内存问题 | 分别记录首次点击和后续点击的响应时间 |
| 4 | 日志文件大小 | 日志过大可能影响写入性能 | 查看 `logs/app.log` 文件大小；当前日志系统已使用 `RotatingFileHandler` 限制单文件 10MB，`backupCount=0` 超出时自动清空重写 |
| 5 | 电脑配置 | CPU 核心数、内存容量、硬盘类型（SSD/HDD）直接影响 I/O 密集型操作 | 任务管理器 → 性能 标签页查看 |
| 6 | 进程资源占用 | 卡顿时 Python 进程的 CPU/内存占用情况可帮助判断瓶颈类型 | 任务管理器 → 详细信息 → 找到 `python.exe`，查看 CPU 和内存列 |

### B.2 性能瓶颈分析指引

> **v1.20.0 已实施优化**：以下耗时操作均已移至 QThread 后台线程，UI 不会阻塞：
> - 图片预览导出 → `PreviewExportWorker`
> - 音频解密 → `AudioDecryptWorker`
> - 批量合成图视频导出 → `CompositeExportWorker`
> - 批量普通文件导出 → `BatchExportWorker`
> - `_as_temp` 复制 + 修复 → `_FixWorker`
>
> 若卡顿仍然出现，应优先检查是否在 UI 线程中执行了新的同步操作。

根据上述信息，可初步判断瓶颈类型：

| 症状 | 可能原因 | 优化方向 |
|------|----------|----------|
| 首次点击卡顿，后续正常 | SpineViewerCLI 导出耗时（I/O 密集） | 检查 `.skel` 文件数量和大小；确认硬盘为 SSD |
| 每次点击都卡顿 | 缩略图渲染或内存不足 | 检查 `output/character/` 图片数量；考虑分页加载 |
| CPU 占用 100% | SpineViewerCLI 或 FFmpeg 子进程满载 | 属正常现象，等待子进程完成即可 |
| 内存占用持续增长 | 图片缓存未释放或 `QPixmap` 泄漏 | 检查 `DragListWidget` 的 `QListWidgetItem` 是否正确回收 |
| 硬盘 I/O 等待高 | 大量小文件读写（如 .bank 解密、PNG 导出） | 确认硬盘类型；HDD 下小文件 I/O 性能较差 |

### B.3 日志系统现状

当前日志系统（`app/core/logger.py`，v1.20.0 已优化）配置：

- **日志分割方式**：按大小分割（`RotatingFileHandler`），固定文件名 `logs/app.log`
- **maxBytes 限制**：✅ 10 MB（`maxBytes=10*1024*1024`）
- **backupCount 限制**：✅ 0（仅保留当前文件，超出大小时自动清空重写）
- **编码**：`utf-8`（支持中文字符）
- **日志级别**：DEBUG（文件）/ INFO（控制台）
- **配置代码**：

      log_file,
      maxBytes=10 * 1024 * 1024,
      backupCount=0,
      encoding="utf-8"
  )
  ```
